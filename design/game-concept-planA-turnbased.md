# 《烽燧·长城攻防》游戏概念文档 —— A 方案·回合制战棋版

> **状态**：讨论稿 v0.1（2026-09-20）｜ 待用户拍板后升级为定稿
> **产出**：文策渊（design-strategist）｜ GW-P1-001 ｜ 主理人汇编
> **姊妹方案**：B 方案·即时战略版（另行立项讨论，见 `game-concept-planB-rts.md`）

## 1. 游戏定位

- **一句话 Pitch**：你执掌一段长城的守御，在匈奴潮水般的攻势下，用塔防式建设与战棋式微操守住每一座烽燧。
- **电梯陈述（30 秒）**：这是一款回合制策略游戏。每一关，你在限定资源下于城墙与马道上布置床弩、礌石、火油，排布戍卒；随后匈奴大军携云梯、冲车、投石机来攻。战局在"长城立体地形"上展开——高度即优势，城墙即战线。守则烽火相传，破则山河洞开。

## 2. 设计支柱

| # | 支柱 | 一句话解释 |
|---|------|-----------|
| P1 | 一墙之隔，两种战争 | 攻守双方资源、行动、胜利逻辑完全不对称，拒绝镜像对战 |
| P2 | 高度即力量 | 所有攻防计算以"高度层"为第一变量，占位先于火力 |
| P3 | 每段城墙都有故事 | 决策围绕具体垛口/马道/烽燧展开，地形叙事优先于抽象数值 |
| P4 | 侥幸守住的快感 | 难度刻意压到"濒临失守"线，胜利来自最后一轮的极限调度 |
| P5 | 烽火即语言（氛围支柱） | 火光、狼烟、号角承担叙事，不靠长文本 |

## 3. MDA 分析

| 层 | 内容 |
|---|---|
| 机制 | 回合制行动点；高度差修正命中/伤害；器械有架设/发射/装填相位；资源按"粮饷"计 |
| 动态 | 建设期押注敌方主攻方向→攻城期火线告急拆东补西；保留预备队 vs 前置火力的博弈；烽燧传讯制造信息差（未点亮段落看不见敌情） |
| 美学 | 主体验：**濒危坚守的悲壮感**；次体验：布防完的"棋手安心"、破械瞬间的智斗爽感；情绪曲线：安心→紧绷→濒崩→险胜 |

## 4. 核心玩法循环

| 阶段 | 内容 |
|---|---|
| A 建设阶段 | 用粮饷购买/修理设施、部署戍卒、修墙（是否限时 → 开放问题⑤） |
| B 敌军阶段 | 侦测范围内可见敌军部署；匈奴按 AI 计划推进 |
| C 攻防结算 | 按速度序逐单位行动；玩家单位可手动操控（战棋微操）或托管为自动（塔防化，难度选项） |
| D 补给阶段 | 结算粮饷收入、烽燧援军到岗、失败判定 |

- **胜负**：守方败 = 任意 3 座烽燧失守或帅帐被破；攻方败 = 波次耗尽/士气崩溃
- **关卡结构**：战役制，一关 = 一夜至数夜的连续波次；关与关之间考虑 Roguelite 式半永久建设继承（开放问题③）

## 5. 核心系统清单

| 系统 | 说明 |
|---|---|
| 防御设施 | 床弩（直射穿透一列）、滚木礌石（沿墙砸梯，一次性）、金汁/火油（范围持续伤害+点燃云梯）、城墙弩炮（对器械特攻）、烽火台（视野链+援军调度节点，被毁则断援）、戍卒小队（近战堵垛口，可阵亡） |
| 经济/资源 | 单一资源"粮饷"（屯田产出+击杀缴获+烽燧补给线），多资源留待 Alpha 再加 |
| 士气/高度 | 匈奴方士气条：器械被毁/伤亡过半/主将阵亡触发溃退；守方高度优势 = 每高一层命中+10%、近战受击-10%；**云梯登城即抹平高度差——攻防矛盾核心** |
| 天气/时辰（Beta） | 夜战降视野、大风偏移火矢、大雪冻械，做变量调味不做成核心 |

### ★ 地形方案对比（本草案最大决策点）

| 方案 | 形态 | 优点 | 缺点 | 适合度 |
|---|---|---|---|---|
| A 多层立体战棋 | 六边形/方格 3D 地图，城墙为抬高层，地面为低层，梯道连接 | 完整发挥长城立体感；战棋深度最大；与现有 Three.js 场景气质契合 | 关卡编辑与寻路成本高；高层遮挡低层需处理 | 战棋正统，产能重 |
| B 2D 横向剖面 | 侧视纵剖面，敌从右向左，类似"王国：新大陆"×塔防 | 开发最省；高度差天然直观；氛围易做得电影化 | 策略深度偏塔防而非战棋，"棋"感弱 | 快速验证 MVP 玩法 |
| C 折中：立体战棋+剖面辅助 | 战斗主视图用 A，但限"单段城墙+有限坡道"的走廊式关卡 | 保住战棋深度，关卡可控；剖面作爆点演出/结算视图 | 两套视图的 UI 工程量 | 长期形态，MVP 不建议直接上 |

## 6. 匈奴 vs 守军 兵种/设施对照表（克制核心）

| 匈奴方 | 定位 | 被克制方 | 守军反制 | 克制逻辑 |
|---|---|---|---|---|
| 骑射手 | 远程骚扰、点杀戍卒 | 无盾戍卒 | 垛口女墙（格挡）、床弩 | 机动换血，怕掩体 |
| 云梯步兵 | 多点攀城、消耗高度优势 | 单点火力 | 滚木礌石、金汁 | 人海爬墙，怕垂直打击 |
| 冲车 | 撞门/撞墙，破结构 | 高层直射火 | 火油纵火、城墙弩炮 | 结构威胁，怕火与重械 |
| 土坡台（土坡） | 堆坡道抹平高度差 | 全体城墙火力 | 弩炮点名、出城焚坡 | 战术级"拆高度"，逼守方出墙 |
| 地道工 | 绕过城墙从内破防 | 静态防线 | 烽燧侦测（听瓮）、预备队堵口 | 惩罚"只守墙不留兵" |
| 投石机 | 超远程拆设施 | 设施与垛口 | 出城夜袭（主动出击指令） | 惩罚龟缩，逼玩家冒险 |
| 狼骑督队 | 斩杀溃兵、维持攻势 | 士气机制反弹 | 烽燧连弩伏击、斩首行动 | 敌方"士气锁"，先杀督队可引发连锁溃退 |

**克制设计三原则**：① 无万能解（每威胁至少两种反制）② 克制是"效率差"而非"免疫" ③ 高层设施克制低层威胁、地面兵种克制登城威胁，与 P2 支柱自洽。

## 7. 范围分层

| 阶段 | 内容 | 判据 |
|---|---|---|
| MVP（4-6周） | 方案B剖面或最简立体图；3 种守军设施（床弩/礌石/戍卒）；4 种匈奴兵（云梯/冲车/骑射手/督队）；单资源；5 关线性战役；托管式自动战斗+手动微操开关 | 能完整打完 5 关且"濒危险胜"手感成立 |
| Alpha | 立体战棋化（或升级至方案C）；+金汁/弩炮/烽火台/地道/土坡；士气系统；6-8 关+难度梯度；数值平衡表 | 无主导策略；克制表闭环 |
| Beta | 夜战/天气；援军调度玩法；Roguelite 继承或战役地图；音效美术包装；教学关 | 可对外试玩版本 |

## 8. 视觉锚点与美术方向

沿用现有 Three.js 场景基因：暗夜底 `#0d0f16`、朱砂红 `#b3382c` 点缀（烽火/按钮/警示）、米白 `#f7ead6` 文字。方向：**"水墨夜巡"**——低多边形+雾气纵深感，攻方黑潮压境、守方暖光孤城，色彩对比承担阵营识别。烽火传讯做成全局光视觉语言（一段烽燧亮起→地图边缘渐次点亮），叙事不靠字幕靠火光。UI 用简牍/朱印元素，克制不堆料。

## 9. 引擎/平台选型

| 选项 | 优势 | 劣势 |
|---|---|---|
| A Three.js 网页 | 复用现有 0.7MB 场景与美术基因；零安装即点即玩；AI 代码协作生态最好；迭代演示最快 | 战棋要自写寻路/回合框架/AI；无编辑器，关卡靠代码生成；性能上限低于原生 |
| B Godot 4 桌面 | 用户已有 Godot 4.7.2+GUT 经验；TileMap/Navigation/回合框架生态成熟；导出 Web+桌面双端；长线工程化最强 | 现有 Three.js 资产需重做/迁移 |
| C Unity/其他 | 生态大 | 用户无经验背书，单人+AI 模式下学习成本不划算，不推荐 |

**推荐倾向：A 起步、B 备选**——MVP 用 Three.js 快速验证玩法手感（现有场景直接变关卡原型），若 Alpha 决定上立体战棋且工程复杂度爆炸，再评估迁 Godot。核心逻辑层用纯 TS/JS 写成引擎无关模块，降低迁移税。

## 10. 关键设计风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 玩法身份模糊 | 塔防化 vs 战棋化路线分叉，做歪就是"另一个植物大战僵尸" | MVP 先锁定"回合+微操"的手感验证关 |
| 立体战棋产能陷阱 | 3D 寻路+遮挡+关卡编辑器可吞掉数月 | MVP 限"走廊式关卡"，编辑器推到 Alpha 后 |
| 单侧 AI 弱则崩 | 匈奴 AI 若只知冲脸，不对称设计全废 | AI 用"意图脚本+目标评分"而非真寻路博弈，MVP 就留评估接口 |
| 数值平衡黑洞 | 克制表 8×8 手调无底洞 | Alpha 起建数值表+模拟器批量对拍 |
| 主题深度风险 | 匈奴题材需注意历史尊重与文化表达尺度 | 定位"边塞史诗"而非民族对立叙事，文案逐条把关 |
