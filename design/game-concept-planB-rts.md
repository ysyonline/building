> 讨论稿。与 A 方案（回合制战棋版）共享世界观、克制骨架与美术方向；核心差异在操作模型与体验：A 是"落子前的长考"，B 是"长考被没收后的本能与决断"。

## 1. 游戏定位

- **一句话 Pitch**：匈奴的云梯已在十段城头同时架起——你不是棋手，是亲临城头的守将，在同一分钟里决定哪里先救。
- **电梯陈述（30秒）**：即时战略游戏。没有回合，敌军潮水般压向长城，警报从烽燧一路燃到帅帐。你实时调度戍卒小队堵缺口，亲手拍下滚木砸落云梯，下令火油泼向冲车，同时分神让民夫把下一桶油送上来。屏幕永远比你的手快一步——在崩溃蔓延之前按住它，就是这款游戏的快感核心。

## 2. 设计支柱

| # | 支柱 | 说明 |
|---|------|------|
| B-P1 | 一秒三令 | 操作密度即体验：每 10 秒一个"必须现在处理"的决策点，拒绝空闲 |
| B-P2 | 烽火即命令 | 烽燧链是玩家的"提前量"：烽燧被毁→预警缩短→被迫救火式反应（A 案信息差的实时化） |
| B-P3 | 可控的混乱 | 混乱是燃料不是噪音；每波攻势都保证存在一条"高手操作线"，力挽狂澜可达成、可复现 |
| B-P4 | 高度即节奏 | 保留"高度即力量"DNA：敌兵爬墙需 8 秒，这 8 秒就是调兵时间窗（替代回合公式） |
| B-P5 | 亲临城头 | 镜头贴墙、火光扑面，临场感优先于全局鸟瞰的整洁 |

## 3. MDA 分析（RTS 版）

| 层 | 内容 |
|---|---|
| 机制 | 实时 tick 驱动；命令队列与执行延迟；器械装填冷却；粮饷流速经济；预警提前量参数 |
| 动态 | 多防区告急时的"救火排序"；民夫冒死补给 vs 断火抉择；斩督队引发实时连锁溃逃 |
| 美学 | 主体验：**手忙脚乱中力挽狂澜的操作爽感**；情绪曲线为高频脉冲：平稳→警觉→多点爆发→力挽→喘息→再爆发 |

## 4. 实时核心循环

| 并行轨道 | 内容 |
|---|---|
| 经济轨（持续） | 粮饷按秒流入；民夫自动/手动运送补给（火油、箭矢、石料——没弹药就只能看着敌人爬墙） |
| 建设轨（随时） | 任何时刻可下单建造/修理，受限于民夫数与资源流，产生"建设排队"取舍 |
| 战斗轨（主轴） | 波间 2-4 分钟建设窗口，波内 3-6 分钟攻城高潮；强度曲线：佯攻→主攻→齐攻 |

- **时间控制**：建议"随时暂停 + 2x/3x 变速"，暂停时可排队指令（半实时缓冲，对单人开发手感调优友好）→ 开放问题①
- **操作颗粒度**（三层）→ 开放问题②：
  - a. 小队级：框选戍卒小队指派防区/驰援
  - b. 器械热键：滚木礌石、火油、床弩齐射由玩家点击触发（爽点锚）
  - c. 烽火令：消耗稀缺"令箭"发动全段增益（急行军/死守），A 案烽火语义功能化为主动技能

## 5. 核心系统清单

| 系统 | 说明 |
|---|---|
| 实时经济 | 粮饷流速模型（流入/流出/储备）；民夫是经济与前线之间的活体纽带，可被骑射手射杀，护民夫成为新玩法 |
| 实时指挥 | 小队制（每队 10-12 戍卒，全场 5-8 队）而非单兵微操，降低 AI 与玩家双手负担 |
| 器械实时运作 | 床弩/弩炮自动索敌（可手动锁定特攻）；滚木礌石/金汁为冷却制手动点击——"自动火力铺底+手动大招收割"双层结构 |
| 烽火预警链 | 敌情提前 60/30/10 秒三级预警（烽燧全→失一燧降一级），信息差转为实时节奏工具 |
| 士气与溃退 | 匈奴小队士气破则实时掉头奔逃，督队追斩逃兵；玩家用令箭稳定己方（A 案士气机制的实时化） |
| 事件系统（Beta） | 夜袭、风暴断预警、援军到岗倒计时，制造波间节奏钩子 |

## 6. 匈奴 vs 守军对照表（沿用 A 案克制骨架，标注实时化改动）

| 匈奴方 | A 案克制骨架 | RTS 版改动 |
|---|---|---|
| 骑射手 | 怕垛口掩体与床弩 | 实时游走骚扰民夫补给线→新增"护送"微操乐 |
| 云梯步兵 | 怕滚木礌石/金汁 | 礌石变为**冷却 20 秒的手动点击**，十梯齐架时点击优先级即爽点核心 |
| 冲车 | 怕火油/弩炮 | 火油需民夫实时送燃料，"冲车临门却无油"的卡壳危机成为高潮事件 |
| 土坡台 | 怕弩炮点名/出城焚坡 | 堆坡为持续进度条，实时决策"何时值得出城拆坡" |
| 地道工 | 怕烽燧侦测/预备队 | 红色涟漪预警后**预备队 40 秒驰援竞速**——RTS 专属竞速玩法 |
| 投石机 | 怕出城夜袭 | 夜袭队全程玩家框选带队走位，回合指令变为实时微型行动关卡 |
| 狼骑督队 | 斩溃兵维持攻势 | 斩首成功触发实时连锁溃逃动画，情绪冲击比回合结算更即时 |

克制三原则沿用 A 案（无万能解／效率差非免疫／高层克低层）；**数值表两案共享，是双方案复用资产的关键点。**

## 7. 范围分层

| 阶段 | 内容 | 判据 |
|---|---|---|
| MVP（6-8周） | 横向剖面单战场；4 戍卒小队；3 设施（床弩自动+礌石/火油手动）；4 敌兵种（云梯/冲车/骑射/督队）；单资源+民夫；5 波次；暂停+2x | 15 分钟守城战完整可玩，"救火排序"爽感在试玩中可被说出 |
| Alpha | 多防区+烽火预警链+士气溃逃+土坡/地道/投石机；8 关+难度梯度；令箭技能；实时平衡调优 | 无万能策略；波内强度曲线经 5 人以上试玩验证 |
| Beta | 天气夜战、事件系统、战役继承、千级单位性能优化（若达标）、教学 | 可对外试玩 |

## 8. 视觉锚点（与 A 案共享"水墨夜巡"）

- **共享**：暗夜底 #0d0f16 + 朱砂红 #b3382c + 米白 #f7ead6；黑潮压境 vs 暖光孤城；烽火全局光语言。
- **差异**：A 案用高位 Ortho 鸟瞰（棋盘感）；B 案建议**斜 45° 中低机位 + 波内镜头轻推拉**（告急防区镜头呼吸感、溃逃大场面全景）。同屏单位更多，单位造型需更剪影化、可读性优先。

## 9. A/B 方案对比表（选型关键材料）

| 维度 | A 战棋版 | B RTS 版 |
|---|---|---|
| 核心体验 | 棋手运筹，濒危坚守的悲壮感 | 实时指挥，力挽狂澜的爽感 |
| 操作模型 | 回合内无限思考，离散指令 | 实时并行，APM 与优先级判断 |
| 情绪曲线 | 低频高压（安心→紧绷→濒崩→险胜） | 高频脉冲（平稳→爆发→力挽→喘息） |
| 开发最大风险 | 回合 AI 质量决定下限 | 实时平衡+性能+AI 三重压力叠加 |
| 产能压力 | 较低（回合制天然容错，数值可纸面推演） | 较高（手感必须靠可玩原型反复调） |
| 数值复用 | 基准版 | 克制表/兵种数值可直接复用 A 案 |
| 目标玩家 | 策略深度党（Into the Breach 受众） | 操作快感党（They Are Billions、要塞受众） |
| 验证成本 | 低（一个手感验证关即可） | 中（MVP 必须做到"可玩且爽"才算验证） |
| 资产复用 | — | 世界观、克制骨架、美术方向 100% 共享，未来做双模式可合并 |

## 10. 技术选型影响（相对 A 案的变化）

| 维度 | Three.js 网页 | Godot 4 |
|---|---|---|
| 海量单位 | InstancedMesh+Web Worker 可撑数百单位，千级需极限优化 | 多线程+NavigationServer，千级单位有成熟路径 |
| 实时寻路/AI | 全自写，工作量显著高于 A 案 | 导航/避让开箱即用，RTS 主场优势 |
| 帧率与手感 | 浏览器波动影响实时手感 | 原生帧率稳定，输入延迟更可控 |
| 存档/回放 | IndexedDB 可行但自建 | 内建序列化生态 |

- **结论**：RTS 削弱了 Three.js 起步优势。B 案建议"MVP 仍用 Three.js（单位数压在 200 内验证手感）→ Alpha 上千级单位前评估迁 Godot"，或直接 Godot 起步 → 开放问题⑥

## 11. 关键设计风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 手感不可纸面验证 | "爽不爽"只能靠原型迭代 | MVP 第 2 周末出灰盒原型先验操作爽点 |
| 实时平衡黑洞 | 参数耦合比回合制更紧，一处改动全盘震荡 | 参数表集中管理+每波次录像回放对比 |
| 混沌失控 | "可控的混乱"失控即纯挫败 | 每波次设计"保底正确序列"并测试验证 |
| 民夫系统双刃剑 | 护送玩法可能沦为琐碎杂务 | 民夫自动化程度做成难度选项 |
| 性能天花板 | 千级单位在低端机网页端劝退 | 单位数目标降档+剪影化渲染省性能 |

| # | 问题 | 选项 | 推荐 |
|---|---|---|---|
| ① | 时间控制 | A 无暂停纯实时 / B 随时暂停+变速（暂停可排队指令）/ C 暂停限额（TAB 式硬核） | B |
| ② | 操作颗粒度 | A 单兵微操 / B 小队指挥+器械热键 / C 纯点击塔防 | B |
| ③ | 战场形态 | A 横向剖面实时（王国式）/ B 3D 走廊实时（TAB 式）/ C 环形开放防线 | A 起步（与 A 案地形决策相互独立） |
| ④ | 同屏单位目标 | A 数百级（性能稳）/ B 千级（史诗感） | A，Beta 再冲千级 |
| ⑤ | 失败判定 | A 沿用"3 烽燧失守/帅帐破" / B 实时血条式城墙耐久 | A，世界观一致且更有戏剧性 |
| ⑥ | 引擎路线 | A Three.js MVP→Alpha 评估迁 Godot / B 直接 Godot / C 全程 Three.js | A |
| ⑦ | MVP 周期 | A 6 周紧凑 / B 8 周含两轮手感复盘 | B，RTS 手感必须两轮以上迭代 |
| ⑧ | **两案关系** | A 二选一 / B 先 B 后 A（RTS 验证后再补战棋模式）/ C 并行孵化 | A 先定主线；克制表与美术资产两案通用，切换成本已最小化 |
