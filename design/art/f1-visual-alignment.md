## 0. R3 残余风险裁定（先给结论）

**「分层网格视觉表达 × 水墨夜巡」兼容度 = 高，可高保真融入，不需要为玩法可见性牺牲风格。**

裁定理由与三个前提条件：

1. **格线笔触化**：水墨语言最怕 CAD 匀质线框。灰盒期允许直线，正式版格线必须带笔触断续（见 §4.1）——这是把"网格"翻译成"墨线"的关键一步。
2. **层间区分靠色温而非纯明度**：三层用「寒 → 中性 → 暖」的温度梯度（夜地寒 / 砖石中性 / 烽燧暖），暗夜氛围和层级可读性不冲突。
3. **切层半透明直接包装成"雾气"语言**：上层变半透明 + 淡墨描边，视觉上就是"月光穿雾看城"，遮蔽处理本身成为风格资产而非妥协。

满足这三条，R3 关闭；任何一条被打破（尤其正式版退回纯几何匀质线框），需回到本备忘复议。

## 1. 灰盒可读性标准（MVP 灰盒期，给程基岩的直接可用色值）

### 1.0 总原则

- 灰盒期**不用参考场景的黄昏光照**，建议用固定半球光 + 低强度方向光的简单打光（或 MeshLambert 直出），保证下述色值所见即所得；夜景光语言是正式版的事（§4.2）。
- 所有明度对比按 WCAG 相对亮度比计算（下表已算好），验收口径统一。

### 1.1 三层盒子颜色规范

温度梯度设计：**层 0 寒（夜地）、层 1 中性（砖石）、层 2 暖（烽燧火）**——暗夜底色内做层级，不破坏氛围。

| 高度层 | 语义 | 灰盒底色 | 相对亮度 | 与相邻层对比 | 备注 |
|---|---|---|---|---|---|
| L0 | 地面（匈奴集结/冲锋） | `#1b2130` | 0.015 | vs L1 = 2.1:1 | 近夜底 `#0d0f16` 的同族提亮，寒蓝灰 |
| L1 | 墙顶/马道（守军主防线） | `#57534a` | 0.087 | vs L2 = 1.8:1 | 暖中性砖石灰，全图主战场需最稳读 |
| L2 | 烽燧顶（制高点） | `#8a7a5e` | 0.201 | — | 暖琥珀灰，天然带"火光照顶"暗示 |

- 三层任意两层对撞时一眼可辨（对比 ≥1.8:1 + 色温差），无需依赖标注文字。
- 【代价：低】要点：MeshLambert 纯色材质 + 一个固定 HemisphereLight（天空 `#3a4560`/地面 `#1a1512`，强度 0.9），色值直出即可，勿引入实时色调映射干扰色值。
- 【代价：低】要点：若 spike 沿用 ACESFilmic toneMapping，需把上表色值乘 ~1.15 曝光补偿后验色，或灰盒期直接 `NoToneMapping`（推荐后者，验收更简单）。

### 1.2 网格线与地面贴花规格

口诀：**深底粉笔线、亮底墨线**（水墨语言在灰盒期的最低成本表达）。

| 项 | 规格 |
|---|---|
| L0/L2 地面线（深底） | `rgba(158,178,208,0.20)` 冷粉笔线，对 L0 底对比 ≈1.5:1，存在感刚好 |
| L1 墙顶线（亮底） | `rgba(13,15,22,0.55)` 淡墨线，对 L1 底对比 ≈1.75:1，墨线压纸 |
| 线宽 | 等效 2px（1080p、主机位下约 0.04 格宽）；选中/危险加粗到 3px |
| 单元格尺寸 | **1 格 = 4m（F1 GDD v1.2 F1.2 定值，渲染常量，正稿经 spike 相机标定后收口）**；贴花密度按 4m 出规格；若后续偏离 4m 需回传美术复核 §4.1（GDD 侧已承诺） |
| 连接器格标示 | 按三级视觉码执行（§3）：坡道/GATE 双条实边、烽燧梯单条实边、云梯单条虚线（冷青） |

- 【代价：低】要点：`GridHelper` 是全局单层且线宽 1px 不可控，三层各自用 `LineSegments` 自绘格线（每层一次性生成，~几百线段，零压力）。

### 1.3 单位与状态色

**先说一个有意偏离**：概念稿说"攻方黑潮压境"，但**纯黑/深色单位体在夜地 L0 上不满足可读性**（黑压黑）。灰盒与 MVP 期，阵营识别走**色温 + 顶色片**，"黑潮感"由阵型密度与正式版剪影承担，不靠把单位涂黑。此偏离已在 §0 前提框架内，特此标注。

| 项 | 灰盒色值 | 对比验收 |
|---|---|---|
| 守方单位主体/顶色片 | 米白 `#f7ead6` + 深轮廓 `#14110c` | 对 L1 底 ≈6.5:1（≥4.5 ✓） |
| 攻方单位主体/顶色片 | 冷青 `#8fb8d8` + 深轮廓 `#10161c` | 对 L0 底 ≈7.7:1（≥4.5 ✓） |
| 选中态 | 朱砂描边 `#b3382c` 3px + 内衬 1px 米白（双线），明度脉冲 ±8%、周期 1.2s | 任何底色上可辨（朱索单独对 L1 仅 1.29:1，必须双线/脉冲补足） |
| 可移动范围贴花 | `#f7ead6` @ 22% 面填充 | 不盖过格线 |
| 敌方威胁范围贴花 | `#b3382c` @ 28% 斜纹填充 | 与"选中"共用朱砂是刻意的：都是"警示"语义 |
| 设施（床弩/礌石） | 守方色系但形状区隔（床弩=横杆+架，礌石=垛口滚筒），颜色不复用攻方冷青 | 形状先行，颜色辅助 |

- 【代价：低】要点：单位灰盒建议"棋子式"低柱体 + 顶面阵营色片（instanceColor 实现阵营区分，一个 InstancedMesh 收全部单位），顶色片从高位 Ortho 看永远可见，这是战棋可读性的保底方案。
- 【代价：低】要点：脉冲/描边用每帧改 material.color 或 overlay quad 即可，MVP 不上后处理描边。

### 1.4 对比度验收清单（灰盒 spike 完成时逐条过）

- [ ] 三层盒子同屏（主机位）一眼分层，不依赖文字标注
- [ ] 任一单位在其所在格上 ≥4.5:1
- [ ] 网格线可感知但不喧宾（对比 1.2–2.0:1 区间）
- [ ] 选中态在任何格子、任何层上可辨
- [ ] 关掉文字 UI 后仍能答对"这单位在哪层、归哪方、选中了没"

## 2. 切层渲染美术规格

### 2.1 透明度建议值

| 相机档位 | L1 墙层 | L2 烽燧层 | 说明 |
|---|---|---|---|
| 地面档（俯瞰 L0） | **0.35**（区间 0.30–0.40） | **0.28**（区间 0.22–0.32） | 上层保持"雾中剪影"，下层战术信息为主 |
| 墙顶档（俯瞰 L1） | 不透明 | **0.30**（区间 0.25–0.35） | L0 常驻不透明（地面是背景，永远可压暗） |

- 单位在半透明层下时，该单位也 ×0.5 透明度——否则"实体单位悬在雾里"比"一切皆雾"更怪。（**已与 F1 GDD E15 口径对齐：半透明≠不可交互，该层单位可选中性必须保留，P3 禁用 opacity 做点击过滤**；C10 复核操作场景后正式关闭，Q5 转入 §6 已关闭区）
- 半透明层内的**朱砂选中态例外**：当玩家选中半透明层下的单位时，其选中描边不随层降透明（opacity 保持 1.0，仅本体 ×0.5）——选中是最高优先级交互信号，不允许被雾气吃掉。拾取逻辑走 `pickCandidates`（F1 E14），与透明度无耦合。

### 2.2 轮廓化描边

- 半透明态的上层几何加**淡墨蓝灰描边** `rgba(158,200,232,0.60)`、1–2px——"雾气里的墨线轮廓"，让玩家仍能读出墙体走向，同时不会被误认成朱砂的交互态。
- **朱砂红严格保留给交互/警示/烽火**，绝不用于切层表现——两套语义不能混。
- MVP 从简：`EdgesGeometry` 线框叠加即可，不上法线外扩或 OutlinePass（后者留 Beta 包装）。

### 2.3 切换过渡

- **建议 180ms 线性 opacity 过渡**（每层一两个 material.opacity 插值，实现成本近零）；纯瞬时切换（0ms）也可接受，但 180ms 能消掉"层突然消失"的跳变。
- 透明材质统一：`transparent:true, depthWrite:false`；多半透明层间用 `renderOrder` 按高度固定排序（高的先画），杜绝透明排序抖动。

【代价总评：低-中】要点：透明分组 + renderOrder + opacity lerp 都是标准做法；唯一要留意 depthWrite=false 后下层盒子间的自遮挡观感，spike 时肉眼验一次即可。

### 2.4 单格堆叠可视化（新增，回应 F1 GDD §2.5.1 裁定 3 与 OQ-5）

R1 容量表（地面 4 / 马道 2 / 其余 1，堆叠上限 4）意味着同格多单位是常态读数，堆叠必须可读——"这格几个人"是容量环之外的视觉保底。

| 项 | 灰盒规格 | 正式版方向（Alpha 前，不展开） |
|---|---|---|
| 堆叠表达 | 同格单位**紧凑错位排列**：以格中心为圆心、半径 0.22 格的微型环上均布（1→居中，2→对角，3→三角，4→四方），不叠模型——从高位 Ortho 看每个单位顶色片都完整可见 | 同布局；棋子加「队列前后」朝向细节 |
| 数量读数 | 格角单字符计数贴花（`×2 / ×3 / ×4`，米白 90%），同格 ≥2 时显示 | 转笔触小旗或戍牌 |
| 容量环 | 选中含多单位格时，格缘环形进度弧（米白，弧长 = n/cap），呼应 GDD §6.1 `occupancyOf()` 的"格容量环 UI 2/4" | 环转墨圈 |
| 选区框选 | 框选/点选按"格"为最小命中单位（与 F1 CellId 寻址一致），堆叠格一次选中全组；拆选归 P3 微操 | — |
| 交互开放点 | 框选过堆叠格时选中整格还是逐单位拆分——**OQ-5 关闭口径：本备忘建议"点选=整格、再点同格=循环高亮个体（预览），拖出=指令逐个下"**，最终归 P3 GDD，表此为美术侧建议方案 | — |

【代价：低】要点：环上偏移是纯实例矩阵偏移（InstancedMesh setMatrixAt 逐帧可改）；计数贴花走 decal quad 池；容量环 = RingGeometry thetaLength 动态改。

### 2.5 `meta.texture` 美术标签枚举（新增，回应 F1 GDD §3.1 字段留白）

GDD `Cell.meta.texture?` 标注"美术标签（挂 R3，林绘澄，可空）"——给出约定枚举，避免关卡数据里出现自由字符串：

| 枚举值 | 用途 | 表现 |
|---|---|---|
| `default` | 缺省（可省略字段） | 该层标准贴花 |
| `ramp_head` | 坡头格 | decal 提示优先级最高（§6.1 热点位）+ 正式版砖石收边 |
| `gate` | 门洞格 | 门拱轮廓描边 |
| `beacon` | 烽燧格 | 火盆灯位挂点 |
| `deploy` | 部署区格 | 建设期米白淡纹（C7 消费，Phase 内复用 §1.3 范围贴花语言） |
| `spawn` | 敌方出生区 | 冷青警示纹（建设期常显，开战后熄） |
| `teach` | 教学锚点格 | 与 `meta.name` 成对出现，首次触发呼吸光 |

- 约束：枚举外值关卡校验拒绝（并入 GDD §8.4-V13 同一机制）；单格至多 1 值；Alpha 扩枚举需回本备忘登记。
- 【代价：低】要点：枚举→材质/贴花映射表，纯查表。

## 3. 连接器视觉语言

设计原则：**坡道是墙的一部分，云梯是戳向墙的异物**——一眼二分。

**三级视觉码（v1.1 升级，依据 F1 GDD E11 通行权裁定）**：机制两维度正交映射到视觉两维度——**线型 = 可否切断**（实边不可断／虚线可断）、**条数 = 通行权**（双条双方共用／单条守方专属）。三级互不重叠，且不依赖色相即可区分（色盲友好兜底）。

| 连接器 | GDD 依据 | 通行权 | 灰盒编码 |
|---|---|---|---|
| 坡道（SLOPE，L0↔L1/L2） | E11：双方共用，攻方限步兵，不可摧毁 | 双方共用 | **双条实边** `#f7ead6` @60% |
| 烽燧梯（SLOPE，L1↔L2） | E11：守方专属，防直捣帅帐 | 守方专属 | **单条实边** 暖白 `#e8d5b0` @60% |
| GATE 门洞 | E11：GATE=特殊静态 Connector（OQ-1 待 C1 确认），单列通行，封门后 INACTIVE | 双方共用 | 复用坡道双条实边 + 门拱轮廓；INACTIVE 封门时边条转灰 `#5a564d`（呼应 GDD §6.1 灰显） |
| 云梯（LADDER，动态） | §2.4.2/§2.4.4：可架设可摧毁 | 存在期共用 | **单条虚线边条**（冷青 `#8fb8d8`）= 可切断语义 |

| 维度 | 坡道/烽燧梯（静态连接器） | 云梯（动态连接器：存在/被毁两态） |
|---|---|---|
| 形态 | 斜坡盒体（烽燧梯更窄更陡），嵌进墙断面，两侧矮墙裙 | 细长构件，独立架设，探出墙面 |
| 阵营色温 | 随所连层的中性/暖色 | 冷青 `#8fb8d8`（攻方器械语义） |
| 存在态 | 边条常亮 | 常亮 + 两端点格各一个冷青角标（角标 = "这条梯连接这两格"的显式读法，对玩家排兵至关重要；双梯并立 E4 时两梯角标错位摆放防重叠） |
| 被毁态 | 不存在此态 | 见下方反馈序列 |

### 云梯被毁视觉反馈（灰盒版，事件驱动；时序对齐 F1 GDD E5）

1. **0–300ms**：梯身绕脚部 pivot 倾倒（ease-in 旋转 ~70°），无粒子；
2. **300–500ms**：材质冷青 → 去饱和灰（同色相降到 40% 饱和），opacity 1→0.85，残骸躺平留在梯脚——**纯视觉标记，不占格**（GDD E5 裁定）；
3. **同时**：原连接的两端点格角标朱砂闪 2 次（各 250ms）后消失——保证玩家没盯着梯子也能收到"通路断了"的信号；
4. **残骸存续期 = 事件时序**：`DESTROYED` 记录保留至本回合结束（GDD E5），残骸模型随之保留；**下一补给相位收到清除事件后，残骸模型同步淡出（300ms opacity→0）并回收**——表现层只订阅 F1 mutation 事件流（架设/摧毁/清除三事件），**禁止表现层反向驱动图论**，也不自行推测清除时机。

【代价：低】要点：倾倒 = 改 pivot 后 lerp rotation；角标 = 预制 decal quad 池按事件启停；全程无 shader/粒子需求。

正式版升级（Alpha 前目标，本备忘只立语言不展开）：坡道走砖石管线 + 梯道踏步齿；云梯为木质长梯 + 月光冷调 rim 光；被毁 = 断折两截 + 短促烟尘（与 P5 破械演出共用语言，Beta 包装深化）。

**§2.5 §3 代价补记**：堆叠可视化（§2.4）与 meta.texture 枚举（§2.5）均为低代价；三级视觉码相对 v1.0 两级仅多一种边条材质与 GATE 灰显态，代价仍为低，§5 总表结论不变。

## 4. 正式版风格路线（Alpha 前目标：「水墨夜巡」融入方案）

### 4.1 格贴花做法：**Canvas 程序化**（明确推荐，弃纯几何线框作正式方案）

理由：① 与现有管线同血统（参考场景已是 CanvasTexture + triplanarUV + InstancedMesh，见 §4.3）；② 水墨笔触本质是"噪声调制的 alpha 描边"，程序化生成成本极低、手绘反而需要对齐每格 UV；③ 纯几何线框在正式版会露出 CAD 感，直接违背水墨气质。

建议做法：
- **每层一张程序化 CanvasTexture 地板**（一次性生成）：砖石底纹（复用砖缝高度场思路）+ 墨线格（alpha = 0.5 基底 × 噪声调制 + 随机断笔，破匀质）+ 边缘留白渐淡。尺寸预算：走廊 20×4 格 @64px/格 ≈ 1280×256，取 2048×512 留余量，三层合计 <6MB VRAM，一次性成本可忽略。
- **运行时状态（选中/移动/威胁）不重烘贴图**，用 decal quad 池叠加（§1.3 的三态色直接复用为正式版贴花色），贴花边缘同样做笔触羽化。
- 灰盒期照旧用几何线框（§1.2），两套并行、§0 前提 1 在正式版切换时生效。

【代价：中】要点：Canvas 程序化贴图管线参考场景已验证可抄；新增工作量集中在"噪声调制墨线"的参数调校，建议留 2–3 个迭代轮。

### 4.2 垛口 / 马道 / 烽燧顶的材质与光语言

夜景光方案（替换参考场景的黄昏参数，结构不动）：

| 项 | 正式版规格 |
|---|---|
| 半球光 | 天空冷靛 `#22304a` / 地面暗棕 `#14100c`，强度 0.5——整体"月夜"基调 |
| 月光方向光 | 冷灰蓝 `#aebfd4`，强度 0.8，低角度（长影，戏剧感来源） |
| 守方暖光 | 烽燧火盆 / 垛口灯点光源，暖橙 `#ffb36b`，`distance` 限界（防穿层）——"暖光孤城"落点 |
| 烽火全局光 | 烽燧亮起 = 该灯位 intensity 0→2.5 ramp + 邻近烽燧接力点亮（跨烽燧传播属 P5 演出，F1 只需保证层材质支持 emissive + 预留灯位挂点） |
| 相位演出切分（正式版预留） | 相位切换的镜头/光线语言变化（如攻防结算开始 = 暖光收紧、敌军相位 = 冷色渗入）直接订阅 F2 §3.3 相位事件流，F1 侧只需事件可达 P1，无需本阶段实做 |
| 雾 | `FogExp2` 色改深靛 `#10141f`；**密度必须重调**：参考场景世界尺度 4200 用 0.00023，走廊尺度（<100 单位）预估 0.008–0.012，spike 实测定值 |
| 材质 | MeshStandardMaterial + 程序化砖纹（roughness 0.95，无金属度）；垛口/马道砖基色在参考值 (0.72, 0.69, 0.645) 基础上压暗 ~35% 并降暖，靠月光面提亮 |
| 三层材质差异 | L0 地面：粗颗粒 + 更暗；L1 墙顶：砖纹主体 + 垛口投影；L2 烽燧顶：偏暖石色 + 火盆 emissive 点 |

【代价：中】要点：全部是参数改写，无新渲染结构；点光源控制在 ≤8 盏并用 distance 限界，标准 WebGL 前向渲染无压力。

### 4.3 与 great-wall.html 程序化砖石管线的兼容注记

实测参考文件（0.7MB 单文件，three.js r160 内联为全局变量、普通脚本零构建）后的结论：

**✅ 直接复用（管线血统保留）**
- `makeBrickMaps()`：Canvas 砖纹颜色图 + Sobel 高度场法线图（512²，8×4 砖阵 + 明度抖动）——正式版格贴花与墙体材质的底子；
- `triplanarUV()`：盒体三平面投影，砖缝比例与世界尺度一致（垛口 TILE=2.2 / 塔体 TILE=5 的经验值可直接沿用）；
- InstancedMesh + instanceColor（垛口三种实例的做法）——正好是灰盒单位与正式版垛口的实现模板；
- 手写 `mergeSimple()` 几何合并（未用 BufferGeometryUtils，注意别引入新依赖）；
- 工程兜底件：自适应阴影分辨率（WebGL2→4096 否则 2048）、绘制缓冲上限保护、context-lost 提示、加载看门狗——灰盒 spike 建议照搬。

**⚠ 改造（换参数不换结构）**
- 参考场景是**黄昏暖调**（fog `0xe8b184` / 太阳 `0xffc98f` / 天顶蓝 `#2f4576` 系），游戏要**暗夜冷调**——所有颜色参数按 §4.2 重写，shader 结构零改动；
- FogExp2 密度差约 50 倍（尺度不同），见上表；
- 相机从 Perspective 55° 自由视角 → Ortho 固定档位，属新写代码，但场景图完全兼容。

**⚠ 新写（参考场景没有的）**
- 切层透明分组 + renderOrder 管理；decal quad 池；事件驱动的连接器状态机；烽火灯位挂点系统。
