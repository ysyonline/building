#### 1.1.1 一条铁律：数据所有权三级分离

**规则（X2）≠ 账本（X1）≠ 落盘（F5）**。幸存者名单的生命线示例：

```
关末 WIN → F2 产出战局快照（turnEndSnapshots 尾）
        → X2 继承结算函数：读 BattleEndReport v1.1 → 算新 rosterPool（纯计算，无副作用）
        → X1 把新 rosterPool 写入 CampaignLedger（账本写点，唯一）
        → 下关 S0 存档点：F5 把 CampaignLedger 连同分部快照落盘（落盘写点，唯一）
```

X2 的结算函数是纯函数（同输入必同输出，无墙钟无随机），因此**继承结算天然落在确定性纪律保护伞内**——这是 X2 不持有持久物的设计理由，不是实现偷懒。

#### 1.1.2 与 systems-breakdown 职责行的对齐

systems-breakdown 定义：X2=「关与关之间设施/戍卒状态的继承规则（决策③）」、F5=「战役进度与建设状态的落盘/读档」、X1=「关卡流转/胜负结算画面/3 关战役骨架」。本文 §1.1 表格是该行的可执行细化，无冲突。链 B 硬依赖（F2→C7→C6→**X2→F5→X1**）在本文的体现：X2 规则先行（§2），F5 拼装收口（附录 A），X1 流转收尾（附录 B）——正文顺序即依赖序。

### 1.2 定位与决策③的对齐

概念稿定稿 v1.0 决策③：「战役＋半永久建设继承」。「半永久」三字的 MVP 兑现口径（本文核心裁定的总纲）：

1. **「战役」**：三关不是三次独立对局——幸存戍卒名单跨关携带（§2.1-C），玩家在同一支守军身上持续投入情感；战役账本记录三关战果（X1）。
2. **「半永久」**：继承的只有**人**（幸存者），不带**物**（设施/墙体）与**钱**（粮饷）——因为三关 LevelMap 静态结构逐关不同（W=12/16/20、GATE 1/1/2，F1 §10），设施/墙体的格位锚点在关间无法逐字节映射，强行携带即违背 F5 逐字节恢复纪律；钱不带是为保护 F3 三关难度曲线独立调平（§2.1-D 详述）。
3. **「建设」**：每关关初建设阶段（F2 A 相位）玩家用 C7 六指令从零重建防御——这是每关的谋局乐趣来源，不是继承的缺失。「永久感」由幸存者名单＋结算画面的战报叙事承载（P 系统消费）。

## 2. 机制

### 2.1 继承对象四项裁定（决策③ MVP 最小可行方案）

裁定总原则：**能被逐字节确定性承接的才携带；锚点逐关不可映射或曲线价值为负的一律重置。**

#### A｜设施（床弩/礌石）——不携带，每关重建

- **理由一（锚点不可映射）**：设施实体（C3 v1.0.3 §3.1）的 `cellId` 绑定 F1 静态格位，而三关 LevelMap 的墙段长度（W=12/16/20）与连接器数量逐关不同——L1 垛口格在 L2 的坐标空间中不存在确定像。携带即要求逐关手写映射表，MVP 六周预算不容。
- **理由二（相位态无跨关语义）**：`state ∈ {RELOADING, ARMED, …}` 与 `createdTurn` 均为关内相位机产物（F2 权威），跨关清零后设施等价于新建，携带只剩空壳。
- **理由三（玩法价值为负）**：每关关初建设阶段（A 相位）用 C7 六指令重新谋局，是「每关一个新 puzzle」的设计支柱；带着满配床弩进 L2 会跳过谋局直接进入执行，支柱漂移。
- **Alpha 占位**：`facilityCarry` 字段位保留（§2.2），若 Alpha 引入「声望建筑」（跨关专属强化设施），按「模板继承＋关初重新寻址」扩展，届时需 C3/C7 联审。
- **对 C7 §7.2 注记的刷新需求**：C7 v1.0.1 §7.2 注「X2 继承间接：关末设施/存卒格局经 F1/C2/C3 快照自然承接」——本文裁定后该注记的「设施」半句失效，需刷新为「设施不携带；幸存戍卒经 rosterPool 承接（附录 B 流转）」。列 §9.11 待 C7 回执（或主理人授权代落）。

#### B｜墙体（GATE 耐久）——不携带，每关重置

- **理由一（数量不可映射）**：GATE 逐关 1/1/2 座（F1 §10）——L1 单 GATE 的战损状态在 L3 双 GATE 结构中无确定分配，与设施同锚点困境。
- **理由二（依赖未落地）**：GATE `lifetime.currentHp` 字段位与 repairWall 白名单是 F1 W-1 接口需求（C7 v1.0.1 §7.2 申请位，转程基岩侧在途）——MVP 修墙本身依赖未交付能力，跨关携带叠加第二层未交付依赖，红线。
- **Alpha 占位**：`wallCarry` 字段位保留（§2.2）；若 Alpha 引入「城墙工事度」（跨关累积），宿主仍为 F1 静态层注记＋X2 结算，需 F1/C7 联审。

#### C｜幸存戍卒名单（survivorRoster）——携带（MVP 唯一继承物）

- **理由**：①上游数据已备——C6 v1.0.2 §2.4 已将 `garrisonCasualties` 进 BattleEndReport，C2 v1.1.3 §2.1 X-1 注记已定组合态语义，X2 只需「存活总数−阵亡总数」的完备性记账（§4 X2.1），实现成本一个纯函数；②「人活着回来」是决策③「半永久」的最小可感载体，也是 X1 结算画面的情感锚点（P 消费）；③不携带任何关卡结构数据，天然满足确定性承接。
- **C1｜DEPLOYED∧OFFBOARD 组合态残队计入（★ 硬性挂账 1）**：关末幸存者 = **全部存活守方单位，不论关内是否上场**。已购未上场（`DEPLOYED ∧ placement=OFFBOARD`，C2 v1.1.3 §2.1 X-1）= 撤回预备队 = **幸存者**，记 `fromState: 'SURVIVED_OFFBOARD'`；上场存活记 `'SURVIVED_DEPLOYED'`。两类合计进 survivorRoster，与 garrisonCasualties **互斥完备**（对账式 §4 X2.1）。序列 #7 X-1 定案「OFFBOARD 残队=幸存者、记账语义无损」在本文落账。
- **C2｜跨关入场形态**：幸存者在下关关初以 `DEPLOYED ∧ placement=OFFBOARD` 预备队形态存在（复用 C2 §2.1 组合态，**不凭空创建新状态**），建设阶段（A 相位）内由玩家零费再部署（复用 C7 撤回预备队零费再部署通道，零新指令）。未再部署的幸存者默认保持预备队，后续回合 A 相位（建设阶段）可照常部署（C7 窗口纪律不变，部署恒 phase='A'）。
- **C3｜重募费用（承接 C6 v1.0.2 §2.4 挂账「重募费用键归 X2 裁」）**：**裁定 MVP 零新费用键**——幸存者免费（其购买成本已在既往关支付，语义=装备与人员一同存活）；阵亡补充=C7 标准 DEPLOY 全价（F3 兵种造价表，C6 charge 通道照旧）。`campaign.retrain.costPerUnit`（打折重募）键位 Alpha 预留挂 F3，MVP 不启用。此裁定需 C6 回执销账（§9.10）。
- **C4｜名单不带成长**：survivorRoster 只记 `{templateId, count, fromState}`，不带经验/军衔/命名（Alpha 叙事扩展位，转 X2 OQ-2）。

#### D｜粮饷（treasuryCarryRule）——不携带，每关 F3 固定初值（B 案）

C6 v1.0.2 OQ-2 留三选一：A 全额结转 / B 关卡固定初值 / C 部分结转＋关卡初值下限（C6 建议方向 C 案）。**本文裁定 B 案**：

- **理由一（曲线保护）**：三关经济按单关封闭调平（C6 farmBase＋F3 逐关参数）。A/C 案引入「上关结余」自由变量后，L1 的省钱打法会溢出到 L2/L3，三关难度曲线（F3 `perLevel.<id>.initialTreasury` 逐关卡值）失去独立控制点——MVP 无平衡迭代预算，必须把经济自由度压到最低。
- **理由二（战役感最小支撑已足）**：决策③的可感载体已由幸存者名单承担（裁定 C）；钱不带不伤「半永久」感知，结算画面照样呈现 treasuryFinal 供玩家复盘。
- **理由三（实现最简）**：B 案=关初直接读 F3 卡值，零结转逻辑、零对账分支。
- **与 C6 建议方向相左的显式声明**：C6 OQ-2 建议 C 案，本文否决 C 案、采用 B 案——设计裁量权在 X2（派单明示「MVP 最小可行方案由我裁」），但**此裁定已列申请位（§9.9）请主理人复核**；若主理人维持 C 案，本文 §2.1-D/§3.2/附录 B.3 相应三处改写，接口面不变。
- **Alpha 占位**：`treasuryCarry` 字段位保留（§2.2）；C 案启用时 X1 关初初始化读 `max(F3 卡值下限, 结转额)`，单行改动。

### 2.3 幸存者记账规则

1. **口径**：幸存 = 关末结算时刻（F2 §2.5 D④ 判定后）全部存活守方单位。`DEPLOYED ∧ placement=OFFBOARD` 残队计入（§2.1-C1）；`DEPLOYED ∧ placement ∈ 关内格位` 存活单位计入；阵亡单位进 C6 `garrisonCasualties`（既有语义，零改动）。
2. **无第三态**：守方单位不存在「失踪/被俘」——C2 状态机二值（存活/阵亡），记账天然完备。
3. **名单生成时点**：D④ 判胜瞬间，X2 结算函数从 C2 权威存活查询（§2.4.2 原语 `isAlive`）＋placement 快照生成，随战局快照写入 `turnEndSnapshots`（F2 §3.2 既有数组，BattleEndReport v1.1 即其元素类型的升级，追加式兼容）。
4. **上限**：MVP 无 rosterPool 容量上限（三关规模下幸存者上限=兵种造价约束下的自然上限）；Alpha 若开容量，挂 F3 `campaign.roster.poolCapacity` 键位（预留声明）。

### 2.5 重打本关语义（败关处理）

- **LOSE=战役失败终局**（裁定 G）：败局画面（附录 B.6）→「重守此关」按钮→ `LEVEL_INIT(L_n)` 重入，**rosterPool 恢复至进关前快照**（§4 X2.3）——即上关结算后的名单，本关阵亡不计。
- MVP 无限次重打，无难度自适应（OQ-4）。
- **survivorRoster 仅 WIN 有语义**：LOSE 时 BattleEndReport v1.1 中 `survivorRoster = []`（§2.2），rosterPool 恢复走快照不走 report——两条数据路径互不污染。

## 4. 公式

> 统一格式：编号 ｜ 名称 ｜ 变量与单位 ｜ 表达式 ｜ 消费方。本文全部公式为整数计数/布尔判定，零浮点，天然重放安全。

- `X2.1 ｜ 幸存记账完备性对账式 ｜ 入场数 I（人）、关内新购数 P（人）、阵亡数 D（人）、幸存数 S（人）｜ S = I + P − D；且 survivorRoster 总数 = S，garrisonCasualties 总数 = D ｜ 消费方：X2 结算自检、F5 INV-F5-2、X1 账本写点前置校验`
  - 其中 OFFBOARD 残队含于 S（`fromState='SURVIVED_OFFBOARD'` 分量）——X-1 记账语义无损的可执行形式。
- `X2.2 ｜ rosterPool 结转 ｜ 进关前池 B（SurvivorEntry[]）、战报幸存名单 R（SurvivorEntry[]）｜ pool' = B 中 templateId 存量 − 该关入场折量，再并 R（同 templateId 合并计数；fromState 取本关值，历史 fromState 不跨关保留）｜ 消费方：X1 INHERIT 步`
  - 注：入场折量 = 本关实际入场（含预备队）消耗的池内存量；MVP 简化——池即「上关幸存者全集」，本关未上场的幸存者自动滚入 pool'（OFFBOARD 残队语义的跨关延续）。
- `X2.3 ｜ 重打恢复 ｜ 进关前快照 poolBefore（X1 preLevelSnapshot）｜ pool' = poolBefore（整池替换，非合并）｜ 消费方：X1 重打入口`
- `X2.4 ｜ 战役完成判定 ｜ results（长度 3）｜ campaignComplete ⇔ results[0] = results[1] = results[2] = 'WIN' ｜ 消费方：X1 战役胜利画面、F5 战役终局封存`

## 5. 边缘情况（继承面）

- **X2-E1｜全灭守关（WIN 且 garrisonCasualties=全体）**：survivorRoster=[]，pool' 折算后为空池——下关零幸存者纯新购开局，**合法态**。UI 侧结算画面显示「无人生还」叙事行（P 消费），但流程零阻断。
- **X2-E2｜零操作获胜（survivorRoster 全为 SURVIVED_OFFBOARD）**：教学关全 AUTO 零操作可判胜（C9 v1.0 互审已确认 W-V6 破燧红线不阻断判胜、C10 默认 AUTO）——全队未上场=全员残队幸存，`fromState` 全 `SURVIVED_OFFBOARD`，X2.1 对账式成立（I+P−D=S 中全员计 S）。**禁止**把「未上场」误记为阵亡——此即硬性挂账 1 的反例测试锚点。
- **X2-E3｜关内新购未上场即获胜**：关内 B/C 相位新购且 OFFBOARD 的戍卒，同属幸存（§2.3 口径不分购买批次），计入 R——X2.1 中体现为 P 项不减。对账式覆盖。
- **X2-E4｜重打期间跨过 S0 存档点**：重打关初 S0 落盘的 CampaignLedger 已含恢复后的 rosterPool 与 `results[n]=null`——若玩家在重打关内再败，读取该档重入，快照恢复幂等（pool' 恢复至 poolBefore 后再败，仍恢复至 poolBefore）。无累积漂移。
- **X2-E5｜战局快照缺追加字段（旧版本快照重放）**：turnEndSnapshots 中的 v1 快照（无 survivorRoster）若被 X2 结算消费（理论路径：Alpha 旧档迁移）——按追加式纪律处理：缺字段→结算函数拒算并告警（**禁静默降级为空名单**，空名单与缺字段语义不同：前者=全灭，后者=数据不完整）。MVP 无此路径（无旧档），防御性裁定。

# 附录 A：F5 存档系统

> 职责边界见 §1.1；本附录自带八节微结构。版本随主文 v1.0-draft。

## A.1 概述

F5 是**存档收口基建**：把 F2/C6/C9/F1/C2/C3 六分部运行时态＋X1 战役账本拼装为单一 SaveDocument，在 F2 §1.4-F 允许的两存档点落盘，读档时逐字节恢复并校验。F5 不裁定任何游戏语义（语义归各分部与 X2）。

## A.2 机制

### A.2.1 存档时机（严格挂 F2 §1.4-F）

| 触发 | 存档点 | 内容 | 策略 |
|---|---|---|---|
| 关卡初始化完成 | **S0**（INIT→A 边界） | 全新关初态＋最新 CampaignLedger | 写主档 |
| 每回合 D→A 转换 | **S1** | 回合末快照＋同上 | 覆盖写主档（滚动保留上一回合副本 `*.bak`，防写坏） |
| C 相位中段 | **拒存**（F2 §1.4-F） | — | 拒绝事件＋UI 提示（§6）；相位机零污染（PL-2） |
| 战役终局（仅三关全 WIN 封存） | 封存档（只读） | 终态 CampaignLedger＋末关快照 | BE-4 |

**裁定 H：MVP 单槽自动存档**——无暂停菜单手动存档项（Alpha 开手动槽：多槽＋手动触发仍只能命中 S0/S1 等价窗口）。A 相位（建设阶段）存档走 S1 语义等价窗口（回合边界态），实现上 A 相位存档=最近 S1 档＋建设指令流水增量，MVP 简化：**A 相位内不触发落盘**，建设成果随本回合 S1 档落盘——玩家在建设阶段退出=回到本回合最近 S1 态（建设指令重下）。此简化保证存档点唯一性（F2 纪律），代价写入 A.5 边缘 F5-E4。

### A.2.2 确定性纪律（贯穿承诺）

1. 同（存档态，指令序列，F4 种子）→ 事件流**逐字节重放**（F2 BE-2 战役层扩展，主文 BE-5）——F5 的全部设计服从这一条。
2. SaveDocument 内不含墙钟、不含非种子随机数；`savedAt` 仅存元信息区（不参与重放与校验）。
3. 读档后首个事件即重放起点，无「读档后重新推导历史」路径——历史语义全部固化在分部快照与 CampaignLedger 中。
