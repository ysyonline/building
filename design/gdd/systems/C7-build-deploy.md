## 1. 概述

### 1.1 职责定义

C7 是守方**建设期的总闸门**：A 相位指令窗口内，玩家关于「买什么、修什么、把人放在哪、拆不拆」的每一个决策，都以指令形式经 C7 校验（世界合法性）→ 支付（C6 扣费）→ 落地（F1/C2/C3 mutation）的单事务管线生效。C7 **是无状态编排层**：世界权威在 F1/C2/C3，钱的权威在 C6，时间的权威在 F2——C7 只保证「每一笔建设指令合法、可支付、原子落地、可重放」，不做任何数值决定。

一句话：**把「一夜筑防」变成一串每条都算数、每条都能撤回重想的确定指令。**

### 1.2 设计目标与支柱挂钩

| 支柱/定稿项 | C7 落点 |
|---|---|
| 决策⑤ 建设不限时 | 指令窗口无墙钟、无步数上限——限制只来自粮饷（C6）与部署区容量（F1）；「想清楚再下单」由无限时间保证，代价纪律（下单即支付）因此成立 |
| MDA 动态「押注主攻方向」 | 床弩建造时朝向必选+射廊预览（C3 firePreview）：建设期的每个布防决策都是对 B 相位未知的下注——「押错方向」的代价由拆除重建的梯度承担（§5-E5） |
| P2「占位先于火力」 | 部署校验严守 F1 容量账与部署区白名单：垛口/坡头每一个格子都是稀缺资源，部署校验就是占位博弈的规则执行者 |
| P4「濒危险胜」 | 「修理便宜、重建贵」经济梯度（C6 §2.3 既定）经本文修理/重建双指令具象化——护械意识与最后关头的取舍压力由此而来 |
| MVS 确定性纪律 | 指令校验=纯函数（零随机零墙钟）；指令流+下游事件流双轨对账，同（存档态，指令序列）→ 逐字节重放（X5/F5 地基，F2 §2.6 同源） |

## 2. 机制

### 2.1 编排位与窗口边界（与 F2 的接驳）

```
A 相位（F2 权威）：
A① F2 发布部署区/建造预算快照 → C7 消费（仅作 HUD 参考基线，权威恒实时查询，§5-E1）
A② 玩家任意顺序下达指令 → C7 六闸校验 → C6 charge → F1/C2/C3 mutation（事件流）
A③ 玩家确认「开始敌军阶段」→ F2 A→B 迁移（build_phase_closed 事件，P3 据此灰显建设 UI）
```

- **窗口判定的唯一权威=TurnQuery**（`phase='A'`），C7 不自持「窗口开闭」状态；A→B 迁移瞬间未完成的指令不存在（每条指令同步完成，无在途挂单——裁定 B 的直接推论）。
- F2 §2.3「A→B 锁定 A 相位指令队列」的 C7 侧澄清：指令均为**下达即执行**，「队列」语义=事件流中的指令到达序（重放对账键），非「关闭时批量执行」。与 F2 A② 字面一致，无结构冲突（§7.3-1）。
- A 相位内**无 MP/AP 交互**：戍卒部署后不行动（F2 A 相位只改静态布局），重置不耗 MP；全部移动经济属于 C 相位（C1/C2 域）。
- **建设期全手动**（F2 §9 契约 3 继承）：C7 校验窗口不对 C10 开放，C10 不得注入任何建设指令（C6-E7 同源系统化）；托管范围=C 相位战斗行动，建设永远是人拍板。

### 2.2 六指令模型总览

| # | 指令 | 参数 | 窗口 | 费用（C6 PurchaseItem） | 落地 mutation |
|---|---|---|---|---|---|
| 1 | BUILD_FACILITY 建造 | cellId + facilityKind + facing（床弩必填） | A | `BUILD_FACILITY`（build 一口价） | F1 registerFacility + C3 建实体（state=CONSTRUCTING〔床弩〕/ARMED〔礌石〕，写 createdTurn=t） |
| 2 | DEPLOY_UNIT 部署戍卒 | cellId + templateId（MVP 恒 garrison_squad） | A | `DEPLOY_UNIT`（一口价/小队） | C2 deploy（UNDEFINED→DEPLOYED）+ F1 placeUnit |
| 3 | REDEPLOY_UNIT 重置戍卒 | unitId + toCellId（含撤回预备队=OFFBOARD） | A | **零**（已购资产位移不收费） | F1 moveUnit（纯结构 mutation，不经 C1、零 MP 交互）；**撤回预备队分支需 C2 增补状态迁移位（X-1，§2.4 申请）** |
| 4 | REPAIR_FACILITY 修理 | facilityId + Δhp | A | `REPAIR_FACILITY`（按 Δ′ 线性，Δ′=夹取后实修量） | C3 repair(facilityId, Δ′) |
| 5 | DISMANTLE_FACILITY 拆除 | facilityId | A | **零（无退款）** | F1 释放 facilityId + C3 移除实体 + `facility_dismantled` 事件 |
| 6 | WALL_REPAIR 修墙 | connectorId（GATE 段）+ Δhp | A | `WALL_REPAIR`（键位 C6 已预留） | F1 修理 mutation（**W-1 待 F1 落地**，未落地则本指令整体封闭） |

- **指令流单线程串行**：A 相位单人环境，指令按提交序逐条完整执行（校验→支付→落地），后条指令的校验世界=前序全部指令执行后的世界——「并发冲突」坍缩为顺序语义（§5-E2）。
- **双轨对账**：指令流水（C7 记）+ 下游 mutation 事件（F1/C2/C3 发）=重放校验双轨；C7 不发重复的世界事件，仅发指令级 `order_rejected{reason}`（§3.3）。

### 2.3 建造（床弩/滚木礌石）

- **格型约束**：两类设施均限 RAMPART_WALK（C3 §2.2/§2.3 部署位口径）；WALL 结构体、垛口、地面、烽燧顶均拒绝（BAD_CELL_KIND）。
- **设施互斥**：目标格 `facilityId` 必须为空（C3-E12 一格恒至多一设施；C7 预检 + F1 registerFacility 终检双闸）。**两套账**：设施占位与单位容量并行（F1 INV1 v1.3.2）——马道格「1 床弩 + 2 戍卒」合法，建造不预检单位容量。
- **朝向必选**（床弩）：`facing ∈ {±x, ±z}` 为指令必填参数，**无默认值**——强制显式瞄准决策，杜绝「未设朝向」中间态；校验 UI 侧以射廊预览（C3 `firePreview`，A 相位可用——纯函数预览，非 C 相位指令）+ 二次确认承载。礌石无 facing。
- **建成时点语义**：床弩 `createdTurn=t ∧ state=CONSTRUCTING`——当轮 C 不可射（C4.3 setupTurns 推导，本文只保证记账写入）；礌石部署即 ARMED、当轮可投（C3 状态机无 CONSTRUCTING 态）。
- **建造即风险**（C3-E1 承认不解决）：CONSTRUCTING 态有耐久可被摧毁——建造是投资也是暴露，本文不做「建造保护期」设计（不在范围，且稀释 AXIAL 梯点名器械的克制环）。

### 2.4 部署与重置（戍卒小队）

- **戍卒=购买即部署**：DEPLOY_UNIT 一步完成「付费+占格」（无「先购买入库再部署」二段式——预备队不是库存，是未购买）；源状态=UNDEFINED（C2 §2.1），落格后 DEPLOYED。
- **重置=零费位移**：戍卒在 A 相位可任意重置（含撤回预备队 OFFBOARD）——占位纠错必须无损，否则「不限时思考」被悔棋成本架空；重置走 F1 moveUnit（结构 mutation，MP 是 C 相位账户、不经 C1）。**部署费只付一次**：重置/再部署不再扣费（费用绑定「购买」行为，不绑定「摆放」行为——与 C 相位移动不花钱同构）。
- **撤回预备队的状态机申请（X-1，申请位不改 C2 结构）**：C2 §2.1 生命周期现无 `DEPLOYED→UNDEFINED` 迁移（UNDEFINED 语义=未购买）——「撤回预备队」若要求单位回到 UNDEFINED，会与「购买即部署、费用只付一次」模型冲突（UNDEFINED→DEPLOYED 路径绑 C6 charge）。**裁定：MVP 撤回不回迁 UNDEFINED**——DEPLOYED 单位经 F1 placeUnit/OFFBOARD 落位（占位态迁移，F1 §2.6 既有 OFFBOARD 态，零 C2 结构改动），DEPLOYED∧OFFBOARD 组合语义=「已购未上场」（A 相位可再部署，零费用）。X-1 增量申请=请 C2 在下一版对该组合态补一行注记（占位=OFFBOARD 时不入行动序/C8 计划域——本来就不在场上，零行为面新增），拒绝则本文改裁「撤回=仅限 A 相位同带重摆，无 OFFBOARD 分支」。
- **校验同闸**：重置目标格走与部署完全相同的五闸（部署区白名单∧容量∧层位∧阵营∧窗口）——重置不是搬家特权。
- **无数量上限**（MVP）：部署数量受预算与容量双重约束，不设关卡级上限键；若平衡期需上限，F3 加键+C7 校验表加一行，结构位已留（§10 OQ-6）。

### 2.5 修理与重建（含 C6 OQ-3/OQ-4 终裁）

- **修理**：仅对存活设施（state ≠ DESTROYED ∧ SPENT 无修理意义——弹药已尽，hp 满则 NO_DAMAGE 自然拒绝）；**夹取语义**：请求 Δhp > 缺口时自动夹取为 `Δ′ = maxHp − currentHp`，按 Δ′ 报价扣费（C6.3），UI 默认「修到满」、支持部分修理（滑条——钱紧时「只补撑过下回合」是策略性保留）。耐久合法性校验语义归 C3.7（本文消费其接口，不重复定义）。
- **重建边界**（主裁点 4）：

| 维度 | 修理 | 重建 |
|---|---|---|
| 前提 | 实体存活 ∧ hp < max | 格已释放（DESTROYED → F1 E7 释放 facilityId，格恢复纯格语义） |
| 费用 | ceil(Δ′ × cost.repair.perHp)（线性小额） | BUILD 全价（C6 §2.3 既定梯度：修理便宜、重建贵） |
| 实体 | 原实体 hp 提升（id 不变） | **新实体新 id**，createdTurn=t，CONSTRUCTING 重起（C4 §2.5），朝向重选 |
| 校验 | C3.7（Δ′ ≤ 缺口 ∧ 非 DESTROYED） | 同建造五闸（对已释放格照常可写——E7 释放保证 registerFacility 无残留） |

- **时序封闭**：修理仅 A、伤害仅 C（F2-E10 窗口互斥）→「先修后毁同回合」「毁后当回合重建」均不可能；重建最早发生于被毁次回合的 A 相位，且新床弩再叠一层 CONSTRUCTING——**重建的实际生效延迟=两回合**，这是「架设期脆弱」的时间代价完整形（C3-E1/E6 链的指令面收口）。

## 5. 边缘情况

> 裁定者=本文；数值归 C6/C3、结构归 F1、窗口归 F2。格式：编号｜场景｜裁定｜消费方。

### A. 预算与时序

- **C7-E1｜预算快照与实时余额的一致性**：A① 快照（F2 发布）只作 HUD 参考基线；C7 校验恒实时 `EconomyQuery.treasury()`（P3 禁本地缓存报价——C6 §6.3 同纪律）。A 相位**无收入源**（收入唯一窗口=D②，C6 §2.1 预算周期语义），相内余额单调不增——「快照后收入变动」场景在 MVP 结构上不存在；缴获流水登记虽发生于 C 相位（C6 双段式），但入账在 D②，同样不触及相内余额。**裁决：实时查询，无快照一致性问题。**
- **C7-E2｜同格连续指令冲突**：指令流单线程串行——「同格建床弩后再建第二座」被 B3 预检拒绝（CELL_OCCUPIED_FACILITY）；「建了又拆、拆了又建」合法（每条各自原子，钱进钱出按梯度，零退款为沉没成本）；后指令世界=前序指令执行后世界，无竞态窗口。
- **C7-E3｜部署区满**：目标带全部格容满 → 逐格 CELL_FULL，指令拒绝；**无排队/等待机制**（不限时相内等待无意义，玩家自选他格/他带）；墙顶带（dz_wall）与预备带（dz_reserve）是独立白名单不可互换——「预备带挤满导致援军无落点」的关联风险见 E6。
- **C7-E4｜修理与同回合被摧毁的时序**：同回合不可能——修理仅 A、伤害仅 C（F2-E10 窗口互斥，C6-E5 同源）；部分修理不存在「修一半被摧毁」（charge+repair 同事务完整执行，无部分落地）。跨回合链：N 回合 C 相位被毁 → N+1 回合 A 相位修理指令 ALREADY_DESTROYED → 仅可重建（全价+CONSTRUCTING，C7.6）。

### B. 决策纠错

- **C7-E5｜床弩朝向选定后悔**：朝向建成不可改（C3 §2.2，Alpha 前锁定）——纠错路径=拆除（零退费）+重建（全价+重选朝向+CONSTRUCTING 一轮），两指令三重代价（沉没成本+重建费+生效延迟）是「瞄准决策」的重量级表达；UI 侧建造时强制射廊预览+二次确认（§6.1）。若灰盒反馈代价过重抑制实验，平衡杠杆=F3 增设拆除退款比例键（键位预留 `cost.dismantleRefundRatio`，MVP 不设=恒零，§10 OQ-4；**键宿主=economy.json**——LOW-1 联裁，见 OQ-4 行注记）——动表不动结构。
- **C7-E6｜援军 D③ 与玩家部署的落点竞争（F2-E13 联动）**：相位互斥（部署在 A、到岗在 D），同相无竞争；跨回合竞争=玩家把落点区占满 → D③ F1 placeUnit 拒绝 → F2 顺延链（下回合 D③ 首位重试，零丢失，F2 权威）。**裁定：无落点保留机制**——C7 校验只认实时容量，不为援军预留格（保留机制需要「此格已预留」的玩家可见语义+预留账本，MVP 不值）；结构性兜底=关卡表「援军总量 × 落点容量自洽」（C6 §2.6 关卡评审项）+ V12 可达性。援军迟到是战局恶化的自然反馈（C6-E9 同哲学）。
