## 1. 概述

### 1.1 职责定义

F4 是全库**确定性重放承诺的种子源与校验基座**：向唯一消费方（MVP=C5 命中骰）供给跨平台逐位一致的随机值序列，记账每一次随机消费（结算流水 settlement log），并把「种子→游标→流水→校验和」四者绑定为可随档落盘、可读档恢复、可重放对拍的闭环。F4 只裁**域内四件事**：PRNG 选型、种子模型与派生规则、游标语义、流水结构与 checksum 签名——**不碰任何消费方机制语义**（命中怎么判归 C5.2、重放从哪起步归 F5.2，本文只供数与供证）。

一句话：**把「这一骰为什么是这一点」变成一个有种子、有坐标、有签名、可复现的答案。**

### 1.2 设计目标与支柱挂钩

| 支柱/定稿项 | F4 落点 |
|---|---|
| P4「濒危险胜」 | 命中骰确定且可溯源——任一次 MISS/HIT 都能经游标坐标反查骰值与判定输入复现（PL-1），玩家对赌的是公开规则不是黑箱 |
| 决策⑥ 引擎无关 | PRNG/哈希全部为纯 TS 整数运算模块，零 Three.js 依赖；规范字节流跨平台逐位一致（BE-2），X5 对拍地基 |
| F2 §2.6 确定性纪律 | 本文是「一切随机经 F4 种子」条款的实现本体：全库唯一运行期随机入口＋唯一 `Math.random` 豁免位（种子生成，不进重放） |
| F5 存档一致性 | F4State 随档落盘（游标随档恢复裁定 §2.3）＋checksum 供给 INV-F5-3——存档完整性护栏的签名端 |

### 1.3 非目标（Non-goals）

- ❌ 消费方机制语义（命中判定公式、修正合成、结算时序）→ C5/C2/F2，本文零重定义。
- ❌ 通用事件总线 / 全事件流录制 → F1 mutation 事件总线归 F1；事件流可重放由 F2 §2.6＋各系统事件序保证，F4 只供 RNG 消费路径见证（§2.4 理由一，§9.4-3）。
- ❌ 数值与概率定值 → F3 表宿主（经 C5 读表消费，F4 不读 F3——零依赖，§7）。
- ❌ 密码学安全 / 对抗性防篡改 → 非目标；F5 INV-F5-3 拒载是**完整性护栏**，不构成安全边界（单机单玩家场景）。
- ❌ 多线程种子分割、Alpha 平衡模拟器实现、密码学级哈希 → 范围红线，均不做。

## 2. 机制

### 2.1 PRNG 选型裁定：mulberry32（终裁）

三候选按派单四标准（确定性/状态体积/序列质量/实现简单）对表：

| 候选 | 状态体积（随档负担） | 实现复杂度（引擎无关 TS） | 序列质量 | 跨平台逐位一致 | 裁定 |
|---|---|---|---|---|---|
| **mulberry32** | **32 bit＝4 B**（全库最小） | ~6 行：`Math.imul` 整数运算＋一次 2 的幂除法；审计面最小 | 周期 2³²；PractRand 小状态电池的有限告警**已知悉**——对命中骰用例（非对抗、非密码、单战役骰量 ≤10⁵，远离质量墙）无影响 | ✅ 全程 u32 整数运算＋`state/2³²` 为 2 的幂精确除法（结果可被 IEEE 754 双精度精确表示），跨 JS 引擎逐位一致 | **✅ 采纳** |
| xoshiro128** | 128 bit＝16 B（4×于 mulberry32） | ~15 行，4 字状态＋scrambler 维护 | 三者最优 | ✅ 同为全 u32 运算 | 备选——质量对本用例过剩、状态随档体积 4×，MVP 不取 |
| PCG32 | ≥64 bit | 64 位乘法在热路径需 split-mul 技巧或 BigInt（慢＋JSON 序列化痛点），实现复杂度税最高 | 优 | BigInt 路径确定但慢 | ❌ 否决——复杂度收益比最差 |

**规范性算法定义**（规范=整数数学，代码为忠实直译；实现可内联但运算序不得重排——乘加不满足结合律重排会破坏逐位一致）：

```
step(x):                                        // 全程 mod 2^32
  t = (x + 0x6D2B79F5)
  t = imul(t ⊕ (t ≫ 15), t ∨ 1)
  t = t ⊕ (t + imul(t ⊕ (t ≫ 7), t ∨ 61))
  t = t ⊕ (t ≫ 14)
  return t

rand():  state ← step(state);  cursor ← cursor + 1;  log 追加 10B 条目（§2.4）;
         return state / 2^32                    // ∈ [0,1)，2^32 个等距格点
```

- **[0,1) 值域精确成立**：state ∈ [0, 2³²−1] ⇒ state/2³² < 1 恒真——C5.2「rand∈[0,1)」的值域承诺由算法结构保证，非约定。
- **零态无不动点**：mulberry32 先步进后输出，state₀=0 第一步即偏移，无需禁用任何种子字。
- **非密码学声明**：mulberry32 可由输出反推状态——本用例无对抗方，接受；F4 不承诺存档防篡改的安全性（见 §1.3）。

### 2.2 种子模型：字符串签名零改动＋展开规则补全

- **签名保全**：`meta.f4Seed: string`（X2 附录 A.3 既有字段）**类型与语义零改动**——本文只补全「字符串→内部状态」的展开规则，不改签名。这就是 §1.4-B 裁定。
- **展开规则**：`state₀ = FNV1a32(utf8(f4Seed))`（F4.2）。
  - FNV-1a-32 规范：`h ← 0x811C9DC5；逐字节：h ← (h ⊕ b) × 0x01000193 (mod 2³²)`。
  - utf8 编码=TextEncoder 语义（UTF-8 无 BOM）；任意 UTF-8 串可作种子（含中文/测试夹具串），展开恒成功、恒确定——**零失败模式**（边缘面 C，F4-E7）。
  - 选 FNV-1a-32 而非 hex 直解析的理由：hex 解析要求种子恰为 8 位规范形（对 Alpha 手输种子、夹具串不鲁棒）；FNV 一步收编全部合法输入，且与 checksum 的 FNV-1a-64 同族——**共享一套原语、两种输出宽度**，实现与审计双重复用。
- **规范生成形**：`newSeed()` 返回 **8 位小写 hex**（16⁸≈4.3×10⁹ 种子空间，MVP 充裕）。熵源=平台随机（**全库唯一 `Math.random` 豁免位**）——生成发生在战役创建期（meta 层，X1 新战役流调用一次），先于任何重放语境；一旦写入 `meta.f4Seed` 即固化为字节，重放确定性不受熵源影响（F5 A.2.2-2「SaveDocument 不含非种子随机数」合规：种子本身即指定的随机载体）。
- **种子生命周期（跨关单链）**：X1 新战役 → `newSeed()` 一次 → 随 L1 首个 S0 落入 `meta.f4Seed` → L2/L3 的 S0 **复制同种子**（不轮换）→ 封存档同种子。理由：①X2 BE-4「封存档回放整场战役」要求三关一条 log 链一个种子即可全程对拍；②每关换种需 X1 增设种子轮换步=跨界机制，MVP 不引入；③确定性无差异（换种与不换种都确定，单链更省）。种子创建**所有权=F4 的 newSeed、调用时机=X1 新战役流、落盘宿主=F5 meta**——三方各归其主。

### 2.3 游标语义与读档恢复（★ 本文核心裁定）

**裁定 C-1：全局单流单游标（非每结算入口独立）。**
依据三条：①F2 §7 依赖行「C8 计划评估与 C5 命中骰**共用其种子流**」——「共用」即单流，这是既有契约不是本文新裁；②C5.8 的游标是单数语义（「每次 rand 调用游标 +1」），StrikeReport.seedCursorBefore/After 夹逼（INV-C5-4）在全局序中才能定位**唯一**坐标——per-entry 游标会让同一坐标在不同入口下含义漂移，对拍锚失效；③MVP 最小——单流＋消费纪律（C6/C9/C10/X3 零消费静态扫描、C1 禁 Math.random）已够安全岛闭合。

**裁定 C-2：游标随档恢复，「读档后从重放起点重算」否决。**
论证四条：

1. **游标是历史偶发性量**：cursor=本战役至今的 rand 调用总次数——它取决于「过去发生了几次攻击」，是指令历史的函数，**不是任何世界状态快照的函数**。存档六分部（f2/c6/c9/f1/c2/c3＋campaign）中不存在能推导出它的输入。「派生物则不入档」的前提（派生自档内数据）不成立。
2. **F5.2 重放起点语义要求游标在档内**：`replay(d) = apply(d.meta.f4Seed, d.*, commandsSince(d))` 的起点=d 的快照态；BE-2/BE-5 要求重放事件流与**原会话尾部逐字节相等**⇒ 重放起点的 RNG 位置必须等于原会话存档时刻的位置⇒ 游标必须 ∈ d.*。若读档重置 cursor=0，原会话存档时 cursor=847、重放从 0 起，骰值序列错位、命中结果不同、事件流分叉——BE-2 直接违约。
3. **F5 A.2.2-3 明禁重推导路径**：「读档后首个事件即重放起点，**无『读档后重新推导历史』路径**」——从关卡起点重算游标恰是被禁路径的字面命中。
4. **C5-E15 已预期**：「F5 存档含 seedCursor 快照——读档→同指令→同报告，『打过了的骰子不会重摇』」。本文以 F4State.cursor 兑现该预期，C5 侧零改动（§9.4-2 确认非勘误）。

**结论**：游标=入档本体。落位 `F4State.cursor`（§3.1，SaveDocument 新增必选分部 `f4`，增补走 §9.3-3 代落）。F5.2 公式**零改写**——`d.*` 自然含 f4 分部，重放起点语义原样成立。同时与 F5 A.2.2-2 合规：F4State 三字段（cursor/state/log）均为 `(f4Seed, 指令序列)` 的确定函数，无墙钟、无非种子随机。

**读档恢复语义**：`restore(F4State, f4Seed)` → 先校验（INV-F4-1/2/3，§4）→ 后 **O(1) 直读恢复**（state 字段直读，不从 seed 重放步进 cursor 次；步进重导仅作校验模式断言 INV-F4-2）。恢复后首个 rand 从存档时刻的下一格点继续——**打过的骰子不重摇**（C5-E15 兑现）。

### 2.4 结算流水（settlement log）：收入口径与条目结构

**收入口径裁定：只收「rand 消费事件」，不收全事件流。**理由三条：

1. **职责聚焦**：F5.1 checksum 的要义是给「RNG 消费路径」一个逐字节见证——骰序一致即确定性最脆弱环节被钉死（任何骰序分叉必然级联为事件流分叉，反之骰序一致＋各系统自身 INV 联保=事件流一致）。全事件流录制是新建第二事件系统：事件所有权各归其主（F1 mutation 归 F1、相位事件归 F2 §3.3、结算明细归 C5 StrikeReport），F4 收编即越权。
2. **体量可控**：骰条目 10 B 定长，全战役 ≤10⁵ 骰 ⇒ log ≤ ~1 MB 上界、典型几百 KB 内；全事件流不定长且含大载荷（走廊目标集/对账明细），随档落盘预算不可控。
3. **对拍充分**：X5/BE-5 对拍断言链=同指令序 ⇒ 同骰序（log 逐字节对拍，本文供给）⇒ 同事件流（各系统 INV 联保）。log 是**最短见证**，无需冗余收录。

**不入流水的东西**（显式排除，防实现走样）：伤害数值、死亡连锁、状态迁移、经济对账——它们的追溯凭据各有宿主（StrikeReport/C6 IncomeReport/F2 事件），F4 不重复记账。

**条目结构（10 B 定长）**：

| 字段 | 宽度 | 语义 |
|---|---|---|
| opTag | 1 B | 消费形态枚举：`0x01=HIT_ROLL`（MVP 唯一枚举=C5.2 命中骰）；0x00 非法保留 |
| domainTag | 1 B | `0x01=CORE`（MVP 恒值）；`0x02=C8_NOISE` **仅编码预留**（C8.5 钩子 MVP 不启用，§2.7） |
| cursorBefore | 4 B | 本骰消费前全局游标 |
| cursorAfter | 4 B | 本骰消费后全局游标（≡before+1） |

- **cursorAfter 显式冗余的理由**：①链自检内嵌——相邻条目 `entry[i].cursorAfter == entry[i+1].cursorBefore` 恒真（F4.5），断链即脏档，INV-F4-1 免重放即可定位第一处不连续；②前向兼容——Alpha 若引入一次调用消耗 k 个随机数的复合操作（洗牌类），`after−before=k` 自然泛化，条目结构不动。
- **append-only 纪律**：流水只追加、不回滚、不裁剪。流水记录的是「RNG 消费事实」而非「游戏效果」——即便 C5-E14 结算回滚（纯护栏，fuzz 断言 MVP 恒不触发）发生，已消费的骰条目也**不回撤**（F4-E2：回滚路径一旦真实触发即构建级警报，会话 log 与任何干净重放必分叉，这正是护栏存在的意义）。

### 2.5 字节序编码规范（S 的规范字节流）

**总则四条**：①**定宽**——偏移可静态计算，INV 逐字段校验；②**显式小端**——LE 是主流平台原生序但必须**显式声明**：JS TypedArray 平台序、DataView 默认大端，均不可依赖，规范=「按 LE 语义编解码」而非「按平台」；③**零浮点**——浮点是编码歧义之根（NaN/次规范数/文本化舍入），流水内零浮点（X2 §4「零浮点天然重放安全」同源纪律）；④**零变长**——流水内无字符串字段，唯一变长物（种子串）在 meta 层不入 S。

**S 结构（logSchemaVersion=1）**：

| 段 | 偏移 | 宽度 | 类型 | 语义 |
|---|---|---|---|---|
| header.magic | 0 | 5 B | ASCII | `"F4L0G"`——流标识，防误拼接/误类型 |
| header.logVer | 5 | 1 B | u8 | 流水结构版本，本文=1 |
| header.seedWord | 6 | 4 B | u32 LE | 种子展开字（=state₀，F4.2）——**跨档移植检测**：A 档 log 配 B 档种子必不匹配 |
| header.entryCount | 10 | 4 B | u32 LE | 条目数（空流=0）——长度篡改可检，空流 checksum 良定义 |
| entry.* | +0 起 | 10 B/条 | §2.4 表 | 按 append 序排列 |

- **S = header ++ entries（追加序）**；空流合法（关初 S0 零骰=S 仅 header），checksum 恒可算。
- header 绑定（magic/version/seedWord/entryCount）参与哈希——S 的身份与内容一体签名，移植、截断、跨档拼接全部可检。
- `F4State.log: number[]` 存储的**就是** S 本身（Uint8Array 语义）——存档形态与哈希输入同物，无二次序列化歧义。log 落盘编码（number[] vs base64）归实现期与工程侧定；无论何种编码，哈希输入恒为字节语义（S 本体），INV-F4-3 不受落盘编码影响。

### 2.6 checksum 签名定稿（X2 A.5 F5.1 占位销账）

```
checksum = hex16( FNV1a64( S ) )
FNV1a64(bytes): h ← 0xCBF29CE484222325；逐字节：h ← (h ⊕ b) × 0x100000001B3 (mod 2⁶⁴)
hex16(h): 64 bit → 小写十六进制 16 字符（前导零保留）
```

- **算法裁定：FNV-1a-64**（对比 xxHash64）：①实现 ~15 行 vs ~80 行——确定性审计面小一个量级（每一处乘加都必须逐位可审计，短=可控）；②速度在体量面前无意义（S ≤ ~1 MB 上界、典型几百 KB，FNV 逐字节毫秒级，且只在 S0/S1 与读档时各算一次）；③非对抗场景（MVP 单机存档完整性＋重放报警）质量足够。xxHash64 列为 Alpha 替换位：若 X5 批量对拍出现性能剖面证据，H 作为 F5.1 的参数整体替换（结构不动，但需 schemaVersion 递增＋全库重放基线重建，§10 OQ-3）。
- **截断长度裁定：不截断（全宽 64 bit）**。`meta.checksum: string` 无宽度压力，64 bit 全宽把偶然碰撞压到 2⁻⁶⁴ 量级——Alpha X5 千次级批量对拍下生日界仍充裕（~10⁹ 次比较才近 2⁻⁷ 量级碰撞面）。X2 A.3 `checksum: string` 类型零改动。
- **实现等价声明**：BigInt 直译=参考实现；`Math.imul` 高低位 split-mul=等价许可实现。规范=整数数学，两种实现必须逐位同输出（BE 断言，BE-6）。
- **销账声明**：至此 X2 附录 A.5 F5.1 的 H（算法＋截断＋输入编码）三要素齐备——**「X2 §9.13 对齐义务已可履行」**，销账素材与代落清单见 §9.3。

### 2.7 Alpha 升级路径（只列位，MVP 一律不做）

| Alpha 项 | 方案占位 | 触发条件与代价 |
|---|---|---|
| per-domain 子流（C8 噪声启用） | `state_tag = FNV1a32(utf8(f4Seed) ++ 0x3A ++ utf8(tag))`（`:` 分隔防拼接歧义）；每子流独立 cursor/state/log；F4State 演进为 `{streams:[{tag,cursor,state,log}]}`，schemaVersion 递增 | C8 OQ-5 Alpha 评审启用；收益=AI 噪声不再推移 C5 骰位（域隔离）；C5.8/INV-C5-4 在 CORE 子流内语义不变；需 C5/C8/F4/F5 联审＋重放基线重建 |
| 流水轮转（跨关裁剪） | 旧关 log 封存＋锚点条目携带前段 H 续链，封存档回放分段验证 | OQ-2；MVP 体量预算内免轮转（§5-B） |
| X5 批量对拍接口 | 「重放生成 log → 与存档 log 字节比对」的批量 API 面 | X5 GDD 落盘时对齐（OQ-3） |

## 3. 数据

> 引擎无关 TS。F4 唯一持久物=F4State（随档落盘）；运行态与持久态同构（F4 模块即 F4State 的活实例），无第二种形态。

### 3.1 F4State 与 SaveDocument 落位

```ts
// F4State —— F4 唯一持久物（SaveDocument 新增必选分部 f4；签名交割与代落走 §9.3-3，本文不改 X2）
interface F4State {
  cursor: number;      // u32 语义：全局游标（已消费 rand 总数），单调 +1
  state: number;       // u32 语义：PRNG 当前内部态（O(1) 直读恢复；重放步进仅校验模式用）
  log: number[];       // 规范字节流 S 本体（Uint8Array 语义，§2.5）——checksum 的直接输入
}

// SaveDocument v1 终形落位示意（待主理人代落 X2 附录 A.3）：
//   meta.f4Seed: string    —— 既有字段零改动（定稿=规范化形态 8 位小写 hex，展开规则 F4.2）
//   meta.checksum: string  —— 既有字段零改动（定稿=16 位小写 hex，F4.4）
//   f4: F4State            —— F4 引致的唯一结构增补（必选分部，非可选——游标无安全缺省，F4-E4）；
//                             INV-F5-2「分部齐全」清单同步增补 f4 行
```

合规声明：F4State 三字段均为 `(f4Seed, 指令序列)` 的确定函数——无墙钟、无非种子随机（F5 A.2.2-2 逐条合规）；f4 必选分部化后，F5.2 的 `d.*` 天然含 f4，公式零改写。

### 3.2 对外接口（F4Api，全库唯一运行期随机入口）

```ts
type F4OpTag = 'HIT_ROLL';                     // MVP 枚举：C5.2 命中骰是唯一消费形态
interface F4Api {
  newSeed(): string;                           // 8 位小写 hex；唯一 Math.random 豁免位（战役创建期 meta，不进重放）
  init(f4Seed: string): void;                  // 新战役：state=F4.2 展开、cursor=0、log=header-only
  rand(op: F4OpTag): number;                   // [0,1)：state 步进→cursor+1→log 追加 10B 条目
  cursor(): number;                            // 只读——C5 StrikeReport.seedCursorBefore/After 的供给源
  snapshot(): F4State;                         // F5 S0/S1 落盘取数（F4 侧零拷贝引用即可，落盘由 F5 编排）
  restore(s: F4State, f4Seed: string): void;   // F5 读档恢复：先 INV-F4-1/2/3 校验，后 O(1) 直读
  checksumOf(logBytes: number[]): string;      // F4.4——INV-F5-3 对拍原语（F5 编排调用）
}
```

- `rand` 强制携带 opTag：消费形态进流水，P4 溯源与对拍分域的前置（代价一个字节，审计收益长期）。
- C5 的唯一消费路径：`strike` 结算中逐目标 `rand('HIT_ROLL')`，前后 `cursor()` 快照进 StrikeReport——C5.8/INV-C5-4 原样成立，F4 不感知结算语义。

### 3.3 读写边界（谁写谁读）

| 数据 | 写入方 | 读取方 |
|---|---|---|
| F4State.cursor / state / log | 仅 F4（经 rand / restore） | F5（snapshot/restore 编排）、C5（cursor 只读） |
| meta.f4Seed | X1（新战役经 newSeed 生成）→ F5 落盘 | F4（init/restore）、F5（F5.2 重放入参） |
| meta.checksum | F5（save 时经 checksumOf 编排写入） | F5（INV-F5-3 对拍）、X5（Alpha 对拍占位） |
| rand 返回值 | — | C5.2 消费即弃——F4 不留存骰值；骰值可由 `step^k(seed)` 重导出（PL-1 溯源路径） |

## 4. 公式

> 统一格式：编号 ｜ 名称 ｜ 变量与单位 ｜ 表达式 ｜ 消费方。本文全部公式为整数运算＋2 的幂精确除法，零浮点累计。

- `F4.1 ｜ 随机值 ｜ state∈[0,2³²)（u32）、rand∈[0,1)（2³² 等距格点）｜ rand() = step(state′)/2³²，其中 state′ 为 step 步进后的新态（§2.1 规范）｜ 消费方：C5.2`
- `F4.2 ｜ 种子展开 ｜ f4Seed:string（X2 A.3 既有签名；规范形=8 位小写 hex）｜ state₀ = FNV1a32(utf8(f4Seed)) ｜ 消费方：init/restore`
- `F4.3 ｜ 游标推进 ｜ cursor∈[0,2³²)（u32）｜ cursor′ = cursor + 1（每次 rand 恰一次，全局单流；调用序=消费发生序）｜ 消费方：C5.8/INV-C5-4/F5`
- `F4.4 ｜ 校验和 ｜ S=规范字节流（bytes，§2.5：header 14 B＋entries 10 B/条，定宽小端零浮点）｜ checksum = hex16(FNV1a64(S)) ｜ 消费方：F5 INV-F5-3（X2 A.5 F5.1 的 H 定稿）`
- `F4.5 ｜ 流水链自洽 ｜ entries e₁…eₙ、cursor ｜ ∀i: eᵢ.after = eᵢ.before + 1 ∧ eᵢ₊₁.before = eᵢ.after ∧ cursor = eₙ.after（n=0 时 cursor=0）∧ header.entryCount = n ∧ header.seedWord = state₀ ｜ 消费方：INV-F4-1、F5 INV-F5-2`

### 4.1 不变量（可单测）

- **INV-F4-1｜链自洽**：F4.5 全式成立——restore 时校验，违者拒载（挂 F5 INV-F5-2 结构校验族）。
- **INV-F4-2｜四角互证**（校验模式断言，dev 构建启用）：`expand(meta.f4Seed) = header.seedWord` ∧ `step^{cursor}(state₀) = state` ∧ log 链与 cursor 相容——防 seed/state/cursor/log 四者被分别篡改后单点自洽；生产构建可降级为抽样校验（Alpha 再裁）。
- **INV-F4-3｜checksum 对拍**：`checksumOf(f4.log) = meta.checksum`——由 F5 INV-F5-3 消费执行，F4 供 H 与 S。
- **INV-F4-4｜原子追加**：rand 内部无重入点，条目追加原子——单线程确定性模型前提（范围红线，多线程分割不做）。
- **INV-F4-5｜全库随机入口唯一**：F4 模块外零 `Math.random`（唯一豁免位=newSeed 熵源，不在重放路径）；与 C6 INV-C6-5 / C9 INV-C9-4 / C10 INV-C10-1 / X3 SC-4 / C1 §2.6-3 的各系统静态扫描互为对偶。

## 5. 边缘情况

> 裁定者=本文。格式：编号｜场景｜裁定｜消费方。

### A. 游标与消费序

- **F4-E1｜游标超大/uint32 回绕**：MVP 全战役骰量 ≤10⁵ 量级，距 2³² 回绕差 4 个数量级——回绕=编程错误。裁定：cursor 按 u32 语义约束，`cursor ≥ 2³²` 断言即 fail-loud（拒继续，触发 INV 告警），**不做回绕取模**（静默回绕会破坏链自洽与重放对拍，属把错误吞掉的禁手）。
- **F4-E2｜结算回滚后的流水**（C5-E14 联动）：C5-E14 定义回滚=纯护栏、fuzz 断言 MVP 恒不触发；裁定流水 **append-only 不随回滚回撤**——流水记录 RNG 消费事实而非游戏效果，回撤=篡改事实。推论：护栏一旦真实触发，会话 log 与干净重放必分叉（该会话不可对拍）——这是**特性不是缺陷**：它把「发生了不该发生的事」变成可见信号，与 C5-E14「构建级警报」定性一致。
- **F4-E3｜同帧多消费交错**：单线程模型＋rand 原子追加（INV-F4-4）⇒ 不存在并发交错；C 相位内结算序由 F2 槽序/C5.7 序兜底，F4 只保证「谁先调谁先得格点」——调用序即消费序（C5.8 语义），F4 不重排、不缓冲。

### B. 存档与校验

- **F4-E4｜旧档/缺 f4 分部**：f4 为**必选分部**（非可选）——游标无安全缺省：缺字段时默认 cursor=0 会在已消费骰子的档上静默错位骰序，属「静默降级」最恶劣形态。裁定：缺失 → INV-F5-2 结构校验失败 → **拒载＋段错误告警**，不适用 INV-F5-4「默认值＋告警」宽恕（该宽恕仅适用于有安全缺省的字段，如 C10 controlMode=AUTO；本文是反例锚点）。MVP 无旧档，此为防御性裁定（X2-E5 同款纪律）。
- **F4-E5｜log 与 cursor 不一致（脏档/手改档）**：改 cursor 不改 log → INV-F4-1 拒载；删/插末条 → entryCount 与链双检拒载；换 seed → INV-F4-1（header.seedWord 绑定，F4.5 末项）＋INV-F4-2（校验模式）双杀。全部路径=拒载，零静默通过。
- **F4-E6｜log 体量上界**：预算声明——条目 10 B × ≤10⁵ 骰 ⇒ log ≤ ~1 MB 硬上界、典型几百 KB；SaveDocument 总体量增量可忽略（对比六分部快照）。若 Alpha 出现超预算剖面 → OQ-2 轮转方案启用，MVP 零处理代码。

### C. 种子

- **F4-E7｜种子字符串畸形**（空串/超长/非 hex/中文）：展开规则对任意 UTF-8 串恒成功恒确定（FNV 无失败模式）——空串=空字节串的固定哈希，合法但 `newSeed()` 永不产出；非 hex 串（Alpha 手输趣味种子如「烽燧」）照常展开。**零特判、零拒收**——鲁棒性来自「一切皆字节」而非输入校验。
- **F4-E8｜弱种子/全零态**：mulberry32 先步进后输出，state₀=0 无不动点（§2.1）；任意 32 bit 种子字均可。回归测试**要求**固定种子（如 `"DEADBEEF"`）建立固定骰序基线（PL-2）——「弱」种子在测试语境反而是资产。

### D. 重放对拍

- **F4-E9｜同种子不同指令序**：log 必然不同、checksum 必然不同——**预期行为非错误**；对拍只对「同存档＋同指令序」断言相等（F5.2/BE-5 语义），F4 不做也不该做跨指令序的比较。
- **F4-E10｜重放中途 log 分叉**：X5 批量对拍（Alpha）中发现 regen-log 与存档 log 首个不一致条目 → 该条目的 cursorBefore 即分叉坐标，可直达「第几次骰、哪个结算入口」——**流水即确定性事故的定位器**（对拍面板展示首异条目上下文，§6）。MVP 阶段该路径由 BE 断言覆盖，无需 UI。
