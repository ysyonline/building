## 1. 概述

### 1.1 职责定义

C4 是器械的**节拍器**：它不拥有时钟（F2 是全游戏唯一时间权威），只在 F2 事件流上裁定「城头器械何时开火、何时装好、何时哑火」——C 相位内的齐射锚点窗口、装填轮的计数推导、架设时长的通用模型、中断时的状态收敛。C4 无自有状态机、无计时器、无相位枚举；它的全部产出是**时点定义 + 推导公式 + 一个事件**。

一句话：**把器械的节拍变成 F2 时间轴上确定的一段，而不是第二套时钟。**

### 1.2 设计目标与支柱挂钩

| 支柱/定稿项 | C4 落点 |
|---|---|
| P1「一墙之隔，两种战争」 | 齐射窗口是守方火力形态的**时序具象**：匈奴每个行动回合开始前先挨一轮床弩（器械先于人员） |
| P2「高度即力量·占位先于火力」 | 齐射窗口位于一切行动槽之前——「先手压制」由时点保证，高度修正由 C5 在齐射结算内兑现 |
| 克制三原则①「无万能解」 | 床弩克骑射手的**时序机制化**：骑射入场先吃齐射，齐射空窗（装填轮）则是骑射的反击窗口——克制是双向节拍 |
| 决策② 托管+微操混合 | 齐射窗口全自动（锁定偏好微操归 C3），C4 只保证窗口时点确定——托管/手动共享同一段确定性时间 |
| P4「濒危险胜」 | 装填空窗是「最后一轮差一发」的机制来源：节拍压力而非数值压力 |

### 1.3 非目标（Non-goals）

- ❌ 第二时钟源、自有回合计数、任何形式计时器 → **K1 禁令**（§2.1），本文架构红线。
- ❌ 独立「器械相位」（FSM 层面）→ **K2 降级表述**：C 相位内的器械指令窗口，不新增相位态。
- ❌ 伤害数值、命中公式、高度修正系数 → C5（C4 只定**何时**调 strike，不算伤害）。
- ❌ 弹道走廊、投放判定、锁定语义本体 → C3（C3.1-C3.8 全部不动）。
- ❌ 自动索敌/自动投放的决策策略 → C10（消费 facility_volley 结果做评估缓存）。
- ❌ 建造/修理窗口 → C7/C6（A 相位，与本文窗口无交集）。
- ❌ Alpha 投石机「真子相位」机制 → §2.6 占位节，Alpha 启动时另立扩展文档。

### 1.4 关键裁定速览（TL;DR）

| # | 裁定 | 一句话 |
|---|---|---|
| A | 单一时钟源（K1） | C4 零自有状态、零计时器；全部时点=F2 事件流上的锚点，全部轮数=权威 turn 的推导函数 |

## 2. 机制

### 2.1 单一时钟源承诺与齐射锚点（K1/K2 落地，C3 需求①）

**K1 结构化表达**：C4 是无状态服务——输入=（F2 TurnQuery、C3 FacilityQuery、C2 UnitStatsQuery 存活原语），输出=（`facility_volley` 事件、装填状态翻转时点定义、C5 strike 请求物化）。无 TurnState 式持久结构、无 phase 枚举、无 setTimeout。

**K2 表述纪律**：全文以「**C 相位内的器械指令窗口**」指代本文时序结构，禁止「器械相位」作为 FSM 层面表述（文中「C4 相位」类历史措辞一律按此降级解读）。

**齐射锚点终裁（C3 OQ-3 二选一）**：

```
B→C 迁移：F2 发 combat_phase_started
  └─ 【齐射窗口】C4 在该事件处理期内同步结算：
       1. 物化全部可射床弩：{f | kind=BED_CROSSBOW ∧ C4.2 就绪 ∧ C3.4 有目标}
       2. 按 facilityId 字典序（C4.4）逐具：走廊物化（C3.1/C3.2）→ 存活复核（C2 原语）
          → strike（C5 入口，kind=CROSSBOW_VOLLEY）→ 发射记账（lastFiredTurn=t，C3 执行）
       3. 发 facility_volley（汇总载荷，§3.2）
  └─ C① MP 重置 → 行动序快照计算 → C② 行动循环（首个 action_slot_open）
```

- **为何挂在 `combat_phase_started` 处理内（而非快照后）**：①严格满足 C3 §2.1 锚点声明「全部守方单位行动槽开启前」——连守方槽都在齐射之后，「器械先于人员」完整成立；②快照在窗口**之后**计算（F2 §2.4 C①），齐射击杀的单位**天然不入行动序**（比「入序再跳过」更干净，且对 C8 计划评估一致性无害——计划生成于 B 相位，齐射死亡按 C5-E2 同源纪律由槽前复核兜住）；③无需 F2 新增事件——`combat_phase_started` 已存在（F2 §3.3），**F2 v1.0.1 零改动**。
- **确定性**：窗口内结算序=facilityId 字典序（与 C5 多来源序同源）；具内目标序=targetPriority（C3.8）；命中骰走 F4 种子流；窗口无任何非确定源。
- **世界冻结（窗口版）**：窗口期间全状态只被齐射结算改变——F2 §2.2「任一行动槽期间世界冻结」纪律向窗口延伸，窗口与槽同级对待。
- **对 C5 的影响面**：齐射伤害结算走 C5 strike 唯一入口（heightDiff 修正等全按 C5 表）；窗口发生于 `phase='C'` 成立之后——F2-E10「beaconHP 变更事件须携带 phase='C'」断言**天然兼容**，零特判。
- **备选「速度序中按先动」被否**：床弩要进行动序须有 speed 值→侵入 C2 速度域、违背「设施不占单位槽」、需处理速度平局键、循环内阵营切换断点特判——为一点战棋风味引入四处跨系统耦合，MVP 不值（裁定记录）。

### 2.2 F2 OQ-3 复核：设施不占单位槽（C3 需求④的口径面 + 本文裁决面）

- **裁定：临时口径转正式**——设施不占单位行动槽。床弩齐射走 §2.1 锚点窗口（槽结构之外），礌石投放走自由指令（C3 §2.3），均不经行动槽路由。
- 影响复核（三点，全部零改动）：①F2 §2.4 行动序快照=单位域（C2 `speed(u)` 查询单位），设施无 speed 不入序；②C10 托管范围不含设施操作（F2 §9 契约 3、C3 §2.5 已互认），设施托管=独立开关（自动索敌/自动投放策略）；③F2-E7「戍卒全灭、床弩自动守燧」场景依赖本口径——窗口照常运转（§5-E8）。
- 交割：F2 OQ-3 销账建议随文交付（§9.2，经主理人代提，F2 v1.1 一行回填）。

### 2.3 装填轮计数权威（K3 落地，C3 需求②）

- **记账**：床弩发射瞬间记 `lastFiredTurn = TurnQuery.current().turn`（F2 权威回合，F1 镜像同值）。记账执行宿主=C3（发射链内一行写入），**定义权**=本文。
- **推导**（C4.2）：`turn ≥ lastFiredTurn + reloadTurns` → 射击就绪；`turn − lastFiredTurn ∈ (0, reloadTurns)` → RELOADING。装填进度是 **turn 的纯函数**。
- **禁令一（递减计数器）**：设施实体**禁止**存「剩余装填轮数」字段——推导式是唯一权威，双源必漂移（存档版本、事件丢失、读档回溯三个漂移面全被纯函数封死）。
- **禁令二（时钟回拨）**：存档/读档禁止改写 `lastFiredTurn`；读档穿越任意轮后，推导结果与连续推进**逐字节一致**（BE-3 验收；C3-E13「避免存档版本漂移」的同源强化）。
- **状态翻转时点**（C4.6）：C3 显式 state 字段（UI 显示用）的 RELOADING→READY 批量翻转挂在 `turn_started` 钩子按 C4.2 执行（执行宿主 C3）——与查询侧推导双保险，逻辑权威在推导式（canFire 判定含 C4.2，状态字段仅显示加速）。

### 2.4 架设时长模型（C3 需求③）

- **通用模型**：CONSTRUCTING 持续 `setupTurns(kind)` 轮（F3 键，通用骨架）；就绪推导 `createdTurn(f) + setupTurns ≤ turn`（C4.3）——与 §2.3 同一推导纪律，零新机制。
- **MVP 床弩**：`setupTurns=1`——建成当轮（createdTurn=t）在当轮齐射窗口中 `t < createdTurn+1` 不就绪（跳过，§5-E6），下回合起 READY。与 C3 §2.2「最简形：当轮不可射」数值逐字一致。
- **超集兼容声明**：C3 状态机（显式 state + turn_started 翻转）与本文推导式兼容；C3 为 Alpha「架设 N 轮」扩展时**只调 F3 键，结构零改动**。

### 2.5 中断收敛规则（C3 需求④）

- RELOADING / CONSTRUCTING 中被摧毁：`state → DESTROYED`（C3 E6/E7 链），装填/架设**作废不恢复**；`lastFiredTurn`/`createdTurn` 记录保留（审计用，无消费方）。
- 重建=新实体新 `createdTurn`（C7 流程），从 CONSTRUCTING 重新起算。
- **推导式的天然优点**：无计时器即无泄漏——实体亡则回合戳无消费方，不存在「幽灵装填」残留状态。C4 侧中断处理=零代码（收敛由 C3 状态机与推导式自动完成）。

### 2.6 C4-Alpha 扩展节（占位，MVP 不展开）

- **投石机「真子相位」需求登记**：Alpha 投石机为攻方器械单位（C2 侧实体），其「装填 2 轮→发射占槽」式子节拍若产品化，**仍挂 F2 回合计数推导**（K1 不破）——「相位感」由实体状态机 + C2 行动经济表达，**不新建 FSM**。登记为 C4-Alpha OQ（§10 OQ-3），Alpha 启动时另立扩展文档评审，不动 MVP 结构。
- **金汁/火油多轮持续效果**：`startTurn + duration` 推导式复用 §2.3 纪律（预埋，Alpha 机制归 C3 §2.7 接口位）。

### 3.2 `facility_volley` 事件契约（N2 采纳，C3 §2.4① 事件名定稿）

```ts
interface VolleyEvent {
  type: 'facility_volley';
  turn: number;             // F2 权威回合（F1 镜像同值）
  volleyId: string;         // `${turn}_V`——每回合至多一次，确定性 ID（重放对账键）
  results: VolleyResult[];  // 按 facilityId 字典序；空载回合为 []（§5-E1 照发）
}
interface VolleyResult {
  facilityId: FacilityId;
  dir?: Dir4;               // 实际射击方向（自动序取首或锁定偏好，C3 §2.2）
  targetLineup: UnitId[];   // 走廊目标物化序（C3.2，存活复核后实际结算对象）
  strikes: StrikeReport[];  // C5 结算回执（逐目标，StrikeRequest.kind=CROSSBOW_VOLLEY）
}
```

- **发射权**：C4（齐射窗口控制器，在 `combat_phase_started` 处理内同步发出）。
- **时序**：窗口结算毕、C① MP 重置前——即恒早于当回合首个 `action_slot_open`（BE-1 断言）。
- **订阅方**：P1（齐射演出锚点）、P4（开火/装填 HUD）、X5（重放配对校验）、C10（托管评估缓存）、C8（敌床弩节拍情报，经事件流只读）。
- **命名辨析**：`facility_volley`=C4 锚定**事件**（F2 事件流成员）；C5 §6.2 的 `CROSSBOW_VOLLEY`=StrikeRequest 的**请求类型枚举**（strike 调用参数）。两者并存不冲突：一次 volley 事件对应 N 次 strike 请求（N=可射床弩数）。

## 4. 公式

> 统一格式：编号 ｜ 名称 ｜ 变量与单位 ｜ 表达式 ｜ 消费方。数值基准一律标「F3 表宿主」。t=当前回合（F2 权威，无量纲整数）。

- `C4.1 ｜ 齐射窗口锚点：volley(t) 发生于 combat_phase_started(t) 处理期内 ∧ 恒早于当回合首个 action_slot_open ∧ 恒早于 C① MP 重置与行动序快照计算 ｜ 消费方：F2/P1/P4/X5`

## 5. 边缘情况

> 裁定者=本文；数值归 F3/F5。格式：编号｜场景｜裁定｜消费方。

### A. 窗口与时序

- **C4-E1｜零可射床弩的回合**（全部在装填/架设/全灭）：窗口**空转但 volley 照发**（`results=[]`）——事件流配对性（X5 重放结构约束，与 F2-E5 skipped 配对同纪律）；P4「本回合器械哑火」HUD 有锚（`volleyId` 存在 ∧ `results` 空 = 哑火信号，与「无床弩」可区分）。
- **C4-E2｜齐射击杀改变行动序**：齐射死亡发生于行动序快照计算**之前**（窗口在 C① 前）→ 被击杀单位**不入序**（非「入序再跳过」）。F2-E5 语义域=序内死亡（槽开启后），本文语义域=序前死亡，两者互补零冲突。玩家体验：P4 时间轴上敌单位开局即划线——「先手压制」可见。
- **C4-E3｜窗口内床弩被摧毁**：不存在——窗口期间世界冻结（§2.1），唯一变更源=齐射结算自身（床弩不打床弩）；床弩摧毁只发生于守方槽后的敌近战（C3-E5）或 Alpha 投石。防御性断言：窗口内 facility_destroyed 事件数=0（BE 校验）。

### B. 计数与读档

- **C4-E4｜读档穿越 RELOADING 多轮**：C4.2 纯函数推导——发射于 turn 5、reloadTurns=2、读档至 turn 8 → 已就绪，与连续推进逐字节一致（BE-3）。存档**禁止**含「剩余轮数」字段（禁令一，§2.3）。
- **C4-E5｜同回合重复发射防护**：`t = lastFiredTurn` 时 C4.2 对 `reloadTurns ≥ 1` 恒 false → 拒绝。窗口每回合至多一次（volleyId 一致性）+ 推导式双重防线，写路径无旁路。
- **C4-E6｜建成当轮齐射窗到达**：`createdTurn=t → t < t+1` 不就绪 → 窗口跳过该具（C4.3）——C3 §2.2「当轮不可射」/C3-E1「架设期脆弱」在窗口机制下的自然结果，无特判。

### C. 跨系统

- **C4-E7｜锁定跨回合语义（预瞄模型，成文）**：齐射窗口早于本回合任何玩家输入 → 回合 t 守方槽间隙下达的 `lockTarget` **影响回合 t+1 的齐射**。C3-E3「发射瞬间复核+自动补选」兜住跨回合目标死亡。UI 明示「锁定自下轮齐射生效」（§6.3，P3 传递）。
- **C4-E8｜F2-E7 戍卒全灭**：窗口照常——人力约束（C3 裁定 E）仅限礌石投放与手动指令面，床弩**自动索敌无 crew 前提**；器械独立守燧成立（F2-E7 的 C4 侧兑现）。
- **C4-E9｜礌石与窗口的关系**：礌石投放=自由指令（C3 §2.3），**不进窗口、不受窗口时序约束**——C 相位任意时点可投（槽间隙含窗口后）。MVP 红线 F：窗口是床弩专属时序结构。
- **C4-E10｜多燧地图（Alpha 远期）**：齐射窗口是否按烽燧分组分段结算 → 挂 C4-Alpha OQ（§10 OQ-3），MVP 单燧无此问题。
