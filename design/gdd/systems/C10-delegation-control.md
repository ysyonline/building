## 1. 概述

### 1.1 职责定义

C10 是决策②「常规交火托管＋关键轮玩家手动微操」的**机制宿主**：在 F2 C 相位的行动槽插入口上，按每个守方单位的 `controlMode` 路由——AUTO 单位由本文的评分模型在槽开启瞬间即时决策并经 C1/C5 公开 API 下达指令（与手动、与匈奴 AI 完全同轨、无特权），MANUAL 单位挂起等待玩家输入。C10 同时裁定托管粒度（单位级/批量/一键）、切换时点语义（槽边界快照）、AUTO 的行为边界（「不做什么」清单）与托管策略的数据驱动表达。C10 **是玩家的委托代理人而非第二个 AI 对手**：它没有自己的战术意图，只把「玩家不在场时会怎么打」变成确定、可重放、可解释的指令流。

一句话：**把「常规交火」变成一串可托付、可随时收回、与亲手操作完全同构的自动决策。**

术语对照：AUTO=托管（系统决策）；MANUAL=微操（玩家决策）。两者是同一行动槽上的两种指令来源，不是两种游戏模式。

### 1.2 设计目标与支柱挂钩

| 支柱/定稿项 | C10 落点 |
|---|---|
| 决策② 托管+微操混合 | 三粒度托管模型（单位级持久标志+批量语法糖+一键接管/交还）——常规交火默认 AUTO 兜底操作量，关键轮玩家零成本接管；切换只在槽边界生效（F2 契约 2），无隐藏时序 |
| MVP 判据「濒危险胜手感」 | 链 A 终点（systems-breakdown §2.2）：一键接管→精准微操→一键交还的循环延迟最小化；行动时间轴 AUTO 标记让玩家预读「哪些槽会自动跑」；接管语义确定性（下槽必生效）支撑「最后一轮的极限调度」（F2 PL-2 联动） |
| P2「占位先于火力」 | AUTO 评分以堵位价值为一等正项：垛口/坡头咽喉格的空缺驱动戍卒自动补位，占好的位不乱跑（待命=显式候选）——托管行为本身执行占位纪律 |

## 2. 机制

### 2.1 托管总模型与插入口（F2 §9 契约 1/2 的 C10 侧落位）

```
F2 C 相位，速度序行动循环（F2 §2.4）：
  每个 C 相位槽开启 → F2 调 C10.resolveSlot(unitId, slotContext)（契约 1）
    ├─ 读 C2.controlMode(u)（槽开启瞬间快照，槽内恒定——契约 2）
    ├─ AUTO  → C10 同步决策（§2.3 评分）→ 经 C1 applyMoveOrder / C5 strike 下指令
    │          → C2 行动经济报告「耗尽/放弃」→ 槽关闭
    └─ MANUAL → C10 挂起（零操作），P3 指令入口对该槽开放
               → 玩家输入经同一套 C1/C5 API / 玩家「结束行动」→ 槽关闭
```

- **模式标志是持久数据**：`controlMode` 挂 C2 Unit 实体（C2 §3.1 字段宿主），随 F5 存档序列化，跨回合保持直到玩家再切。C10 自身**零持久状态**（决策即时消费即时丢弃，§3.1）——「托管记忆」只有玩家设置的标志，没有 AI 的意图残留。
- **切换单事务**：P3 → `C10Command.setControlMode(selection, mode)` → C2 写入（经 `setControlMode` 入口，C2 §3.6 v1.1.3）→ 发 `controlMode_changed` 事件（P4 挂件即时刷新）→ 该单位下个行动槽按新模式快照路由。槽进行中的单位不可切换（跳过并置「排队」提示，E7）。
- **B 相位 C10 零操作**：匈奴计划生成（C8 B③）期间 C10 无任何活动；仅订阅 `phase_enter` 做上一回合决策缓存清理、订阅槽事件做 HUD 数据（契约 5 订阅面，禁止反向驱动）。

### 2.2 托管粒度与切换语义（主裁点 1）

| 粒度 | 操作 | 数据效果 | 适用场景 |
|---|---|---|---|
| 单位级 | 选中单位→挂件/面板切换 AUTO/MANUAL | 该单位 controlMode 持久翻转 | 关键单位常驻手动（帅帐护卫、坡头堵位核心队） |
| 批量 | 框选/多选→批量切换 | 选集内逐单位翻转（N 次单位级操作的语法糖，零新状态） | 一段墙的群体移交/收回 |
| 一键 | 「全部接管」/「全部交还」（P4 挂件） | 作用域=守方在场 ∧ 本回合槽未开启的单位，全量置 MANUAL / 置 AUTO | 关键轮一键接管；战后一键交还 |

- **一键的作用域精确化**：「本回合槽未开启」——A 相位按=全部在场单位；C 相位中途按=尚未行动者（已行动单位槽已关，不可切）。两个按钮语义完全确定、无隐藏状态，语义上覆盖「关键轮接管」与「交还」的常见操作。
- **否决「接管本轮自动交还」（临时覆盖层）**：需要 C10 自持 batch 标记+F5 序列化+重放面扩大，收益仅省一次手动交还；忘记交还的代价=下回合多点几次（手动槽无超时，不会卡死）——MVP 不值，列 Alpha 候选（OQ-3）。
- **否决持久分组**（墙顶组/坡头组）：分组管理 UI+持久分组数据是认知与实现双重负担，批量框选已覆盖其 80% 场景；Alpha 候选（OQ-5）。
- **否决全局持久开关**：「全场托管/全场手动」会无差别覆盖玩家精心挑选的常驻 MANUAL 单位，破坏混合策略；玩家真要全手动，框选全部即可。
- **默认值裁定（主裁）**：守方单位出生（部署/援军到岗）即 **AUTO**。依据：决策②字面「**常规**交火托管＋关键轮手动微操」——托管是常态、微操是例外，默认 MANUAL 会把决策②倒置为「微操为主、托管需主动开启」。教学关不覆写初值：教学关要教的恰是决策②的核心技能（在托管底板上精准接管），X3 引导脚本在教学的对应回合触发「切换该单位到 MANUAL」步骤即可（归 X3 消费本文 §6 语义）。C2 §3.1 注释「DEFENDER 默认 MANUAL 可切」系撰写期占位，经主理人批准（X-C10-2）已落盘修订为默认 AUTO（C2 v1.1.3，§9.6）。

### 2.3 AUTO 决策模型（主裁点 2——C8 评分框架的守方镜像）

对 AUTO 单位 u 的每个候选行动 c（候选集=stay ∪ {MOVE→c′ | c′∈reachable(u)} ∪ {ATTACK→t | t 满足 C2 §2.4.1 资格}）：

```
Score(u, c) = Σ_def  w_def · Value_def(u, c)      // 正项：堵位价值、杀伤价值
             − Σ_def  λ_def · Cost_def(u, c)      // 负项：暴露代价、绕路代价
             + Σ hook.score(u, c)                 // 可扩展钩子（§2.6）
```

**目标价值项**（正，守方语义）：

| 价值项 | 含义 | 消费接口 |
|---|---|---|
| 堵位价值 blockVal | 候选格对登城通路的咽喉度：是否垛口/坡头/梯顶邻域 × 该咽喉当前空缺度（无友军占位才有补位价值） | F1 `getActiveConnectors`（ACTIVE 梯/坡顶格）、`occupancyOf`、C2 `aliveDefendersIn` |
| 杀伤价值 strikeVal | 近战可及内敌目标的威胁值＋赏格值 × 预估交换比；督队经 `hasAura(t)` 获表驱动增益（赏格键联动，非「点杀督队」硬编码，§9.3 口径） | C2 `unitAt`/`isAlive`/`hasAura`、C6 `loot.perTemplate`、C5 `expectedMods` |

**自身代价项**（负）：

| 代价项 | 含义 | 消费接口 |
|---|---|---|
| 暴露代价 exposeCost | 候选格离开 PARAPET 掩体（cover 分量消失）、进入敌骑射走廊（expectedMods 负向分量放大） | C5 `expectedMods(target)` 逐格（「格在谁脚下谁吃」口径，C8 §9.3 同源） |
| 绕路代价 detourCost | 到候选格的路径消耗（放弃当前好位去次优位的移动税） | C1 `reachable` 代价 |

- **stay（原地待命）是显式候选**：其 Score=表驱动基准 `standFast`——「守住当前位」与移动/攻击同台评分。待命胜出=本槽零指令、经 C2 `actionDone` 收槽（合法决策，非退化）。这使「占好的位不乱跑」成为评分的自然结果而非特判（P2 纪律的托管面）。
- **全部权重/阈值挂 F3 `defense-scripts.json`**（§3.2 键清单）；代码零兵种名/零数值硬编码，查表驱动（C8 §2.6 纪律 2 同源）。
- **督队目标的口径声明**：C8 §2.5 已裁 C2 §2.6「守方 AI 优先点杀督队」原表述 MVP 不成立、反向权重归 C11/C10 消费 `hasAura`。本文认领 MVP 半边：**督队价值经「赏格 × 表权重 + hasAura 增益键」两个表驱动通道进入 strikeVal**——不是硬编码特判，与 C8 §9.1-3 的 Alpha 统一措辞方向相容（§9.3）。

### 2.4 守方行为契约（MVP 戍卒——唯一守方兵种；Alpha 新兵种=加表行）

| 优先级 | 行为 | 触发条件 | 产出指令 |
|---|---|---|---|
| ① 攻击 | 近战互殴/点杀高价值 | 近战可及（C2 `meleeReach`）内有敌 ∧ AP≥1 ∧ strikeVal 胜出 | `strike`（C5 入口，资格已过 C2 §2.4.1，C5 不复检）；攻击后锁足（C2.4），本槽自然收尾 |
| ② 补位 | 移动堵咽喉/撤离暴露位 | 无可攻击目标（或交换比劣）∧ blockVal 最高候选格 ≠ 当前格 ∧ MP 足够 | `applyMoveOrder(MoveOrder{mode:'AUTO'})`（C1 同轨 API） |
| ③ 待命 | 原地驻守 | stay 候选胜出 | 零指令，`actionDone` 收槽 |

- **攻击与移动的自由序**遵 C2 §2.4：「先动后打」合法、「打后移动」被锁足禁绝——AUTO 下单时按「先评估攻击、后评估移动」的固定序枚举，与手动玩家行为面一致（C2-E8 的 C10 侧排序义务）。
- **守方不爬梯、极少留梯**：戍卒经坡道移动（坡顶马道容量 2 难满，C1-E4），唯一理论留梯场景=烽燧梯（容量 1）排队。故 F2 契约 4 的重试槽三选项中，守方 AUTO **恒选「弃梯改令」**（裁定 F）：梯顶必为友军（守方阵地内），等待零收益且吃 `exposedMod`；弃梯后本槽内改下 MoveOrder 至 blockVal 次优格（MP 允许时）。弃梯被拒（C1-E4 终裁：from 格满）→ 本槽零指令收槽。攻方「继续等」（C8-E2）保留——攻方等待=排队登城的战术选项，正是攻守不对称的镜像。
- **设施零托管面（正交声明）**：床弩齐射=C4 锚点窗口自动运作＋C3.8 targetPriority 自动索敌（「托管语义」但宿主在 C3/C4，先于 C10 存在）；床弩手动锁定偏好、礌石投放=C3 自由指令（玩家手动，不占行动槽）。C10 的 controlMode 只路由**单位**槽；MVP 不新增设施托管开关（C4 §2.2 复核②口径，Alpha 候选）。F2-E7「戍卒全灭、设施尚存」场景下 C10 零活动、设施照常——两套自动化互不依赖。

### 2.5 决策时机：即时决策制（主裁——与 C8 预生成制的对照）

| 维度 | C8（攻方） | C10（守方托管） |
|---|---|---|
| 决策窗口 | B③ 批量预生成 UnitPlan[] | 槽开启瞬间（resolveSlot 同步段） |
| 决策依据 | B③ 快照＋本回合 WaveManifest | 槽开启时的实时世界（含此前各槽结算结果） |
| 生成-执行间隙 | 有（同回合内 B③→C②）→ 需 C8-E1 槽前复核兜底 | **零**（决策即执行，世界冻结语境=本槽） |
| 中间计划结构 | UnitPlan 持续到槽执行完 | 无（指令直出，无存续物） |
| 执行 API | C1/C5 公开 API（mode='AUTO'） | **完全相同** |

- **为何不同窗**：C8 需要波次意图上下文（WaveManifest 仅 B③ 完整）；守方无意图脚本，且槽开启时决策读到**更新鲜**的世界（齐射与先行单位已结算）——决策质量更高且天然免疫 C8-E1 类「计划过期」错位（E3）。
- **同轨性的落点**：不在数据结构层（C10 不定义 UnitPlan 对称物——即时制下中间结构无消费者），而在**执行 API 与动作语义层**：MoveOrder（mode='AUTO'）/strike 与手动、与 C8 逐字节同构；冲车类兵种专属分支（C8 §3.1）守方不存在，结构对称性自动成立。C8 §9.1-5 挂账的消费确认见 §9.2。
- **确定性**：决策=快照的纯函数，**零 F4 消费**（命中骰才用种子流）；显式 tie-break（C10.5）取唯一解；同（存档态，种子）→ 同 AUTO 决策序列 → 指令流逐字节重放——AUTO 指令是指令流的组成部分，重放时逐条可对拍（X5/F5 地基）。
- **性能**：单槽决策 P95 ≤ `slotDecisionMs`（F3 键，初值建议 2ms 量级，对齐 C1 reachable <2ms 预算框架）；全守方槽合计远低于 C1 全相位 <50ms 框架（C8.6 同源推导）。

### 2.7 AUTO 的「不做什么」清单（主裁点 4——负空间即设计）

| # | 禁令 | 依据/理由 |
|---|---|---|
| 1 | **不碰 A 相位** | F2 §9 契约 3：建设/部署全手动；C7 校验窗口不向 C10 开放；C6-E7 系统化禁令。模式切换是元操作不是战斗指令，A 相位可切（生效于本回合 C 槽，E10）——禁的是指令注入，不是开关 |

| 3 | **不跨相位记忆** | 决策只读当下快照，无跨回合意图/目标锁；上回合「想堵的口」不残留——玩家每次接管都是干净的起点，AI 无隐藏意志（可解释性） |

## 4. 公式

> 统一格式：编号 ｜ 名称 ｜ 变量与单位 ｜ 表达式 ｜ 消费方。数值基准一律标「F3 表宿主」。

- `C10.1 ｜ 评分框架：Score(u,c) = w_block·blockVal(u,c) + w_strike·strikeVal(u,c) − lambda_expose·exposeCost(u,c) − lambda_detour·detourCost(u,c) + Σ hook.score(u,c) ｜ 全系数 F3 defense-scripts.json ｜ 消费方：C10/P4 overlay`
- `C10.2 ｜ 堵位价值：blockVal(u,c) = throat(c) · vacancy(c) ｜ throat(c) ∈ {0,1}：c ∈ 咽喉集（垛口/坡头格 ∪ ACTIVE 连接器顶格邻域，经 F1 getActiveConnectors+occupancyOf）；vacancy(c)=1 − 友军占堵率（aliveDefendersIn）｜ 消费方：C10`
- `C10.3 ｜ 杀伤价值：strikeVal(u,t) = [threat(t) + bountyWeight·loot(t) + (hasAura(t) ? hasAuraBonus : 0)] · exchangeRatio(u,t) ｜ threat/loot 表宿主 F3；exchangeRatio 消费 C5 expectedMods 预估 ｜ 消费方：C10（§9.3 口径）`
- `C10.4 ｜ 暴露/绕路：exposeCost(u,c) 消费 C5.expectedMods(c) 的 cover 消失与走廊覆盖分量；detourCost(u,c)=reachable 代价（C1 泛洪）｜ 消费方：C10`
- `C10.5 ｜ 显式 tie-break：并列最高分取序 (Score↓, 候选位置格 cellId 字典序, 目标 unitId 字典序, 动作类别序 MOVE<ATTACK<STAY) ｜ 全序无歧义，与 C8.4/C1 §2.6 字典序纪律同源 ｜ 消费方：C10/X5`
- `C10.6 ｜ 决策确定性：decision(u, slot) = f(snapshot(slot), F3 表) 且 f 无内部随机（零 F4 消费）⇒ 同（存档态，种子）→ 同 AUTO 决策序列 → 指令流逐字节重放 ｜ 消费方：F5/X5`
- `C10.7 ｜ 性能预算：单槽决策（reachable+候选枚举+expectedMods）P95 < slotDecisionMs（F3，≤2ms ⚠）｜ 全守方槽合计落在 C1 全相位 <50ms 框架内 ｜ 消费方：实现/性能验收`
- `C10.8 ｜ 待命判定：STAY 合法候选，Score(stay)=standFast（F3 基准）｜ argmax 含 stay，胜出即零指令收槽 ｜ 消费方：C10`

## 5. 边缘情况

> 裁定者=本文；窗口/时序归 F2、执行归 C1/C5、资格归 C2、设施归 C3/C4。格式：编号｜场景｜裁定｜消费方。

### A. 模式切换与双源防重

- **C10-E1｜接管瞬间与已产出 AUTO 指令的冲突（同回合双指令防重）**：**结构性消解，无需防重机制**——F2 契约 2 槽边界快照纪律：槽开启瞬间读取 controlMode 并槽内恒定；槽进行中的切换请求一律排队下槽（C10Command 返回 `queued`，UI 显「下个行动生效」）。AUTO 指令在其槽内原子完成（世界冻结），玩家指令只可能在 MANUAL 槽产生——**双源在时间轴上互斥，不存在并存窗口**。玩家在 AUTO 槽内的点击零响应（P3 指令入口仅对 MANUAL 槽开放），无打断语义。
- **C10-E2｜留梯单位 AUTO 重试与玩家改令的竞争**：不存在竞争——重试槽（F2-E6/契约 4）开启时照常按 controlMode 单源路由：AUTO → C10 即时决策（守方恒弃梯改令，裁定 F）；MANUAL → 等玩家（弃梯/继续等/改令皆可，经 C1-E4 同一裁定面）。上回合的模式切换决定本回合谁做主，同一槽恒一源。
- **C10-E3｜行动序快照后单位死亡，其 AUTO 决策作废**：即时决策制下**不存在「预先产出的决策」**——槽开启才决策，死亡单位槽被 F2 跳过（F2-E5 skipped 成对事件），resolveSlot 不会被调用，零作废逻辑。对照收益：C8 预生成制需 C8-E1 槽前复核兜底，C10 结构性免疫该类错位（§2.5 架构选择的直接回报）。
- **C10-E7｜批量/一键操作遇到槽进行中单位**：逐单位判定——槽进行中者跳过并计入 `queued`（其切换在**本槽结束后、下槽开启前**生效，仍满足「槽边界快照」）；已行动（槽已关）者照常切换、生效于下回合。UI 对 queued 部分显「下个行动生效」。
- **C10-E10｜A 相位切换模式**：合法（切换是元操作非战斗指令，不触契约 3 禁令），生效于本回合 C 相位该单位槽（槽开启快照）。用途=建设期整备托管面（如把预备队全部预设 AUTO）。C10 在 A 相位仍零决策零指令（INV-C10-3 不变）。

### B. 决策环境异常

- **C10-E4｜托管与 facility_volley 齐射的交互**：齐射锚点在全部行动槽之前（C4 TL;DR-B）——AUTO 决策读到的世界恒为**齐射结算后**状态（目标已在齐射中阵亡 → 候选集实时查询自然剔除，无幽灵目标）；AUTO 不代表设施：床弩齐射/索敌是 C4/C3 既定自动运作、礌石投放是玩家自由指令——设施自动化与单位托管**正交**，零耦合零互斥。F2-E7 场景（戍卒全灭）C10 零活动、设施照常守燧。
- **C10-E8｜所有候选均不合格（无目标、无补位格、移动均劣）**：stay 候选恒在集内（C10.8）→ AUTO 待命收槽，合法且零副作用；不降级为「就近乱走」（C1-E7「笨而可靠」哲学的决策层镜像）。
- **C10-E9｜援军到岗单位的模式初值**：出生即 AUTO（默认 B 全局适用，含 D③ placeUnit 与 A 相位部署）——援军是补给叙事，玩家不应为援军做模式管理；下回合 C 相位照常被托管。玩家可随时切 MANUAL。

### C. 存档与重放

- **C10-E5｜读档后 AUTO/MANUAL 标志恢复**：controlMode 是 Unit 字段，随 C2 分部全量序列化（C2-E12），读档逐字节恢复、零 C10 额外持久物；旧档缺字段 → 默认 AUTO＋告警（C2-E12 脏档防线同族，禁静默降级）。

- **C10-E11｜重放一致性承诺（F5/X5 消费面）**：同（存档态，F4 种子）→ 全 AUTO 回合的事件流逐字节重放（C10.6+INV-C10-1/2）；AUTO 指令在指令流中有记录条目，重放器可逐条对拍；`DecisionRecord` 缓存不参与重建（世界权威在宿主系统）。

### 9.4 §6.6 三咬合初裁确认回执（供主理人转美术侧与 P2）

**确认初裁，零修订**：①相机跟随玩家选择、不跟随系统槽开启；②AUTO 槽绝不移动相机（连续槽开启的被动甩镜破坏可读性，且违背「表现不驱动逻辑」克制原则）；③手动槽行动者信息由 P4 屏幕空间 HUD 承载（高亮脉冲＋行动时间轴条目），玩家点击单位或时间轴条目才触发相机档位切换。依据：AUTO 槽占 C 相位大多数且无需玩家注视（HUD 承载足够）；手动槽的跨层选取由玩家主动发起（切档即聚焦，半透明问题在切档后消失）；美术备忘 §6.1 Q8b 注记「零冲突且为净收益」与本确认一致。systems-breakdown §6.6「待 P2/C10 GDD 评审确认」状态可置为已确认（P2 GDD 侧复核仍开放）。

### 9.5 Q5 半透明层内单位可读性——C10 消费面复核结论（供主理人转美术侧归档）

**结论：Q5 在 C10 消费面可关闭，无新增裁决需求。** 复核（场景=美术备忘 v1.1 微补丁精确口径「手动槽内玩家主动跨层选取」）：①AUTO 单位不需要玩家选取——其可读性要求止于「知道它存在且在行动」，由切层规格（备忘 §2.1 单位 ×0.5 透明＋描边）与屏幕空间 HUD（§6.6 确认）承载，半透明层内 AUTO 单位不构成操作风险面；②MANUAL 单位的跨层选取是玩家主动动作——点选该单位（可选中性保留：F1 E15「半透明≠不可交互，P3 禁 opacity 做点击过滤」）或时间轴条目触发相机切档，切档后该层不再半透明，选取发生在聚焦态；③托管操作本身（模式切换）入口在 HUD 挂件与单位面板，不依赖 3D 拾取——半透明不阻碍托管操作。三点合计：Q5 的风险面被「AUTO 槽不动相机＋HUD 承载＋可选中性保留」结构性消解，建议美术侧将 §6.2 Q5 行正式归档（关闭依据=C10 v1.0 §9.5）。
