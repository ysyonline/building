## 1. 概述

### 1.1 职责定义

C3 是守军**静态火力与一次性器械**的宿主：定义设施的通用数据模型（独占占位/耐久/状态）、床弩的弹道与射击循环（消费 C4 相位时钟）、滚木礌石的投放判定与毁梯链路（消费 F1 destroyConnector→E2 坠落链），以及耐久查询与修理接口。C3 不决定「何时开火」的托管策略（C10）、不算伤害（C5）、不校验建造（C7）——它是「火力从哪里来、打哪里、坏没坏」的机制宿主。

一句话：**把「城头上那几件家伙」变成有状态、有射界、会坏会修的机制实体。**

### 1.2 分类学裁定（MVP「3 守军设施」口径的结构归属）

概念稿 MVP 口径「3 守军设施（床弩/礌石/戍卒）」是**内容计数口径**；结构归属如下，全程一致引用：

| 概念稿口径 | 结构归属 | 说明 |
|---|---|---|
| 床弩 | **C3 设施** | 静态火力，独占格，耐久可损 |
| 滚木礌石 | **C3 设施** | 一次性投放物，独占格（弹药库语义） |
| 戍卒小队 | **C2 单位** | 可移动、可阵亡、占单位容量账（F1 §2.5），本文不涉 |

> F1 §2.5.3 括注沿用概念稿计数口径，指「部署期购买物全部独占格」；结构上戍卒归 C2。**GW-P2-003 已统一（OQ-5 关闭）**：措辞定为「部署物（deployables）」＝部署期购买/布设物总称 ⊃ 设施〔C3：床弩/礌石〕＋单位〔C2：戍卒小队〕；F1 §2.5.3 与拆解文档活性引用已按此统一，本节标题与表体作为历史裁定记录豁免。

### 1.3 设计目标与支柱挂钩

| 支柱/定稿项 | C3 落点 |
|---|---|
| P1「一墙之隔，两种战争」 | 设施是守方独占的火力形态（攻方无静态设施，只有器械单位），非对称的结构载体之一 |
| P2「高度即力量·占位先于火力」 | 床弩架于马道获得高度命中优势（修正归 C5）；礌石是「占住垛口就能砸梯」的垂直打击具象 |
| 克制三原则①「无万能解」 | MVP 反制网：床弩克骑射手/地面集群，礌石克云梯；两者互不替代、均需戍卒体系配合（人力约束/近战护卫），无单点通解 |
| 决策② 托管+微操混合 | 床弩自动索敌为「托管面」、手动锁定为「微操面」；礌石投放为关键轮手动爽点（B 案 §6 已验证该爽点锚，回合制化为投放时机抉择） |
| P4「濒危险胜」 | 床弩装填轮空窗 + 礌石一次性 = 火力资源错配压力，最后一轮「石头留给哪架梯」是典型极限调度 |

- ❌ 礌石/床弩的托管自动决策策略 → C10（本文提供判定原语，策略归彼）。

## 2. 机制

### 2.1 设施通用模型

- **占位**：部署时经 C7 校验后调 F1 `registerFacility`，写入 `cell.facilityId`；设施与该格**绑定终身**（不可移动、不可转移）。设施数与单位容量两套账并行（F1 锁定）：马道格可同时存在 1 床弩 + ≤2 戍卒。
- **耐久**：`hp` 由 C5 伤害写入（近战攻击设施、Alpha 投石机轰击）；本文只定义「hp≤0 → DESTROYED」转移与释放链。MVP 中设施的受击来源=登上墙顶的敌方单位近战（AXIAL 云梯的威胁落点，F1 §2.4.3），这正是「梯上匈奴威胁床弩、逼守方留预备队」克制环的机制落点。
- **状态机**（通用骨架，床弩/礌石各自实例化）：

```
床弩：CONSTRUCTING（建成当轮，架设中）→ READY → FIRING（瞬时）→ RELOADING → READY
                                                  └→ DESTROYED（任意态可被摧毁）
礌石：ARMED → SPENT（一次性，投放即终结；可被摧毁）
```

- **行为时点**：床弩射击结算发生于 C 相位（F2 E10：一切伤害仅在 C）；射击时机=固定锚点**「攻方行动段开始前」**（C 相位内全部守方单位行动槽开启前结算一轮床弩齐射——「器械先于人员」，排序细节归 C4 相位时钟，本文只声明该锚点需求）。手动锁定/投放指令在玩家输入窗口（本方任意行动槽间隙）可下。

### 2.2 床弩（BED_CROSSBOW）

- **部署**：马道格（RAMPART_WALK）；朝向 `facing ∈ {±x, ±z}` 建造时选定（Alpha 前不可改向；改向=拆除重建，C7 费用口径）。
- **弹道走廊模型（R2 的 C3 提案，§10 OQ-1 待 C5 裁决）**：
  - 射界=自床弩格沿 `facing` 延伸 R 格（F3 键 `range`）的轴向直线；
  - 穿透：途经**全部敌阵营占位**均被命中判定覆盖（「一列」语义）——含垛口/马道上的敌方登城单位、梯上单位（ON_CONNECTOR 取逻辑位置=梯底格）、地面层单位（俯射走廊覆盖）；
  - **友军豁免**：守方单位不被己方床弩命中（穿透结算按阵营过滤）；
  - **WALL 结构不阻挡**：床弩架于墙顶俯射，弹道从墙体内侧越过垛口线——z 向射击射出走廊界即止（V6 校验保证界外无格）；
  - 逐目标独立应用命中修正（高度差/掩体等，全部 C5 表）。
  - 备选模型 B「同层直线」（仅命中同 h=1 目标，打不到地面骑射手——**不满足克制表**「床弩克骑射手」，故仅作 spike 代价对比项，非推荐）。
- **射击循环**：`canFire ⇔ state=READY ∧ 弹道内∃敌目标`；发射后进入 RELOADING（F3 键 `reloadTurns=1`，即跳过下一轮射击锚点）。建成当轮 CONSTRUCTING（架设语义 MVP 最简形：A 相位建造 → 当轮 C 不可射 → 下回合起 READY；完整架设/装填相位模型归 C4，本文状态机与其兼容）。
- **目标选择**：
  - 自动（托管面）：READY 时锚点到 → 按 F3 键 `targetPriority` 序取首个有目标的射界方向；默认优先级 器械单位 > 督队 > 骑射手 > 云梯步兵（克制表序，数值归 F3 可调）；
  - 手动（微操面）：玩家在输入窗口对 READY 床弩下发 `lockTarget(direction)` 或 `lockUnit(unitId)`——锁定为**偏好覆盖**（发射时目标已亡则回落自动规则，§5-E9），不占行动槽。

### 2.3 滚木礌石（ROLLING_STOCK）

- **部署**：马道格（弹药库语义：一格一具，独占）；ARMED 态无射程概念，投放目标=**云梯连接器**。
- **投放判定**（C3.5）：
  - 目标梯必须 `connKind=LADDER ∧ status=ACTIVE`，且梯顶格（`to`，PARAPET）在该具礌石**投放半径内**（工作假设：同 x 列 ±1 格，F3 键 `dropRadius`）；
  - **人力约束**（裁定 E）：目标梯顶相邻的垛口格或马道格上须有 ≥1 存活守方单位——「有人才搬得动石头」；约束同时是克制网收口（戍卒全灭则礌石哑火，倒逼「守墙必须留人」）。
- **投放效果链**（瞬时，事件驱动）：
  1. 消耗：礌石 → SPENT；
  2. 调 F1 `destroyConnector(ladderId)` → 断边 + 梯上单位坠落位移（F1 E2，F1 执行）；
  3. 对坠落单位追加**砸落伤害**（数值 C5 表键 `dropDamage`，C5 结算）——「梯毁坠亡」与「砸落致死」两条结算入口分离（F1 OQ-2 的 C3 侧立场：礌石伤害只作用于梯上 1 人，恒无范围歧义）；
  4. 梯残骸进入 F1 E5 残骸标记链（视觉演出归 P1）。
- **手动/托管**：投放指令为自由指令（C 相位任意时点，不占行动槽）；托管模式下「何时砸」的策略归 C10（§9 契约 3：C10 只能调 `canDrop` 判定原语，效果链不可绕过 C3 API）。

### 2.4 与 C4 器械相位的消费契约（序列 #5 输入）

C3 对 C4 的需求清单（C4 GDD 须覆盖）：
1. **射击锚点**：C 相位内「攻方行动段前」的床弩齐射时点定义与事件（`facility_volley`）；
2. **装填时钟**：RELOADING 的轮计数权威与时钟回拨禁令（读档一致性）；
3. **架设语义**：CONSTRUCTING 的时长模型（MVP=当轮不可射的最简形；C4 可给出通用「架设 N 轮」模型，C3 状态机兼容超集）；
4. **中断规则**：床弩在 RELOADING 中被摧毁→状态直接 DESTROYED，装填作废（无需恢复）。

### 2.5 与 F2 行动槽的关系（F2 OQ-3 口径的 C3 侧确认）

- 设施**不占单位行动槽**（F2 OQ-3 临时口径，C3 确认采纳为正式口径建议）：床弩齐射走 C4 锚点、礌石投放走自由指令，均不经行动槽路由；C10 的托管范围（C 相位战斗行动）因此**不含设施操作**——设施托管=自动索敌/自动投放策略，是独立于单位托管的开关（§9 契约 3）。
- 此口径下「全员托管」仍需玩家手动确认建设阶段（F2 §9 契约 3：A 相位不开放给 C10），设施在 C 相位完全自动运转（F2-E7 场景成立：戍卒全灭，床弩仍自动守燧）。

### 2.6 摧毁与修理

- **摧毁链**：`hp≤0 → state=DESTROYED → F1 E7 释放 facilityId → 格恢复纯格语义（同格单位不受影响不位移）→ facility_destroyed 事件`。DESTROYED 实体保留记录至回合结束（P1 演出），下回合 D① 清扫退场（与梯残骸同节奏）。
- **修理**：仅 A 相位，C7 指令（费用 C6）；C3 提供 `repair(facilityId, Δhp)` 接口，校验 `Δhp ≤ max−current ∧ state ≠ DESTROYED`（DESTROYED 不可修，重建走 C7 新建流程）。

### 3.1 设施实体

```ts
interface Facility {
  id: FacilityId;
  kind: 'BED_CROSSBOW' | 'ROLLING_STOCK';   // MVP；Alpha 扩展位见 §2.7
  cellId: CellId;                            // 独占格（F1 facilityId 镜像）
  facing?: Dir4;                             // 床弩限定；礌石 undefined
  state: 'CONSTRUCTING' | 'READY' | 'RELOADING' | 'ARMED' | 'SPENT' | 'DESTROYED';
  currentHp: number;                         // maxHp 归 F3 表，禁硬编码
  createdTurn: number;
  lockedDirection?: Dir4;                    // 手动锁定偏好（床弩）
  lockedUnitId?: UnitId;
}
```

### 3.3 对外接口（FacilityQuery / FacilityCommand）

```ts
interface FacilityQuery {
  facilitiesAt(cellId: CellId): Readonly<Facility[]>;      // 恒 ≤1（独占）
  canFire(id: FacilityId): {ok: boolean; targets?: UnitId[]};
  canDrop(stockId: FacilityId, ladderId: ConnectorId): {ok: boolean; reason?: 'NO_LADDER'|'OUT_OF_REACH'|'NO_CREW'|'SPENT'};
  firePreview(id: FacilityId, dir?: Dir4): TargetLineup;   // 弹道走廊预览（UI/托管评估用）
}
interface FacilityCommand {                                 // 仅 C 相位窗口开放（F2 锁口径）
  lockTarget(id: FacilityId, target: {dir?: Dir4; unitId?: UnitId}): CommandResult;
  drop(stockId: FacilityId, ladderId: ConnectorId): DropReport;   // §2.3 效果链
}
// repair(id, Δhp) 归 C7 调用面，本文 §2.6 定义校验
```

## 4. 公式

> 统一格式：编号 ｜ 名称 ｜ 变量与单位 ｜ 表达式 ｜ 消费方。数值基准一律标「F3 表宿主」。

- `C3.1 ｜ 弹道走廊：Line(f, dir) = {f + k·dir | k = 1..R} ∩ 走廊界内 ｜ R = bedCrossbow.range（F3）｜ 消费方：C3/C5/P1`
- `C3.2 ｜ 弹道目标集：T = {u | pos(u) ∈ Line ∧ faction(u) = 攻} ｜ ON_CONNECTOR 单位取 pos = c.from（F1 §2.4.4）｜ 消费方：C3/C5`
- `C3.3 ｜ 逐目标命中：hit(u) 经 C5 结算入口，修正含 heightDiff(pos(u), f)（俯射优势为正）｜ 数值全归 C5/F3`
- `C3.4 ｜ 射击资格：canFire ⇔ state = READY ∧ |T(dir)| > 0；发射后 state → RELOADING（reloadTurns 轮，F3）`
- `C3.5 ｜ 投放资格：canDrop ⇔ stock.state = ARMED ∧ ladder.status = ACTIVE ∧ ladder.connKind = LADDER ∧ dist(ladder.to, stock.cellId) ≤ dropRadius ∧ crewAlive(ladder.to 邻域) ｜ crewAlive = 目标垛口格或相邻马道格 ∃存活守方单位 ｜ v1.0.2 注记（003 门修订）：dist=曼哈顿距离（格数，|Δx|+|Δz|）∧ 轴向约束 |Δx| ≤ dropRadius——z 向邻位合法、纯 z 向偏移（跨轴）不在投放走廊内；初值 dropRadius=1 不变（F3 宿主）`
- `C3.6 ｜ 毁梯链：drop → {stock.state = SPENT} → F1.destroyConnector(ladder) → E2 坠落位移 → C5.砸落伤害(dropDamage, 梯上单位)`
- `C3.7 ｜ 耐久判定：destroyed ⇔ currentHp ≤ 0 → F1 E7 释放链 ｜ 修理：hp′ = min(max, hp + Δ)，Δ > 0 ∧ state ≠ DESTROYED`
- `C3.8 ｜ 优先序：targetOrder = sort(T, targetPriority 序) 取首 ｜ 序归 F3，语义=克制表攻击序`

## 5. 边缘情况

> 裁定者=本文；数值归 C5/C7。格式：编号｜场景｜裁定｜消费方。

### A. 床弩

- **C3-E1｜建成当轮即遭强攻**：CONSTRUCTING 态无射击能力但**有耐久可被摧毁**——建造是投资也是暴露风险（AXIAL 梯点名器械），这是「架设期脆弱」克制环的 MVP 形。完整架设相位模型归 C4。
- **C3-E2｜弹道上友军遮挡**：友军豁免（C3.2 阵营过滤），穿透不停滞——「垛口后戍卒不挡自己人炮」。若平衡期需引入误伤（Alpha 火油），扩 `friendlyFire` 键，不改结构。
- **C3-E3｜锁定目标在发射锚点前死亡**：锁定为偏好——发射时校验目标存活，亡则按 targetPriority 自动补选同方向次优目标；无目标则空转不耗装填（C3.4）。不返还玩家操作，UI 预览即所见。
- **C3-E4｜多床弩同射界**：各自独立结算（走廊重叠合法），无协同加成（MVP 不做）；渲染齐射演出归 P1 合并。
- **C3-E5｜床弩所在格被敌方单位登上**：同格敌我共存（F1 两套账）→ 敌方近战攻击设施（C5 结算，目标=facilityId）；床弩不反击近战（无近战能力），生存靠友军戍卒清剿——「器械必须有人护」的克制网闭环。
- **C3-E6｜RELOADING 中被摧毁**：直接 DESTROYED，装填作废不可恢复；重建=新实体从 CONSTRUCTING 起（C7）。

### B. 礌石

- **C3-E7｜投放时梯上无人**：允许投放（毁梯阻断后续攀爬本身就是价值），砸落伤害无对象——浪费弹药是玩家的代价与抉择（「现在砸断它，还是等爬满再砸」正是礌石的时机博弈）。
- **C3-E8｜双垛口争一架梯**：先到先得——第二指令到达时梯已 DESTROYED → `canDrop` 返回 NO_LADDER，**指令拒绝且不消耗**（校验先行，库存无损）。
- **C3-E9｜人力约束的单位当轮阵亡**：crewAlive 校验在**指令结算瞬间**评估（只查存活，不查 AP——v1.0.1 终裁）——若玩家指令排在戍卒阵亡后，NO_CREW 拒绝；已下达未结算的指令不作废但结算时复核（与 C1 E6 先手结算优先同纪律）。
- **C3-E10｜礌石库自身被摧毁**：ARMED → DESTROYED，弹药报废；同格单位不受影响（E7 链）。
- **C3-E11｜对坡道投放**：**不允许**——坡道不可摧毁（F1 E6），`canDrop` 对 SLOPE 恒 NO_LADDER；UI 侧礌石仅对云梯角标可点（视觉备忘 §3 冷青角标语义复用）。

### C. 通用与跨系统

- **C3-E12｜设施格的部署互斥**：一(cell, facility) 唯一（F1 registerFacility 校验）；「设施占位与单位容量并行」指设施不消耗单位槽，但**一格恒至多一设施**——马道格「1 床弩 + 2 戍卒」合法，「2 床弩」非法（C7 校验，本文声明语义）。
- **C3-E13｜读档穿越 RELOADING/CONSTRUCTING**：设施状态持久化于存档（§3.1 全量）；装填轮计数以 `createdTurn`+F3 键推导而非绝对轮戳——避免存档版本漂移（与 F2 回合权威时钟对齐）。
- **C3-E14｜A 相位下发的锁定/投放指令**：**拒绝**——FacilityCommand 仅 C 相位窗口开放（F2 口径：A 相位只有建造/修理/部署）；预瞄准需求（提前锁方向）列 §10 OQ-4。
- **C3-E15｜托管全开时的礌石**：C10 自动投放策略独立于单位托管开关（§2.5）；玩家可「单位托管 + 礌石手动」混搭——关键轮手动爽点（决策②）的最低保障面。
