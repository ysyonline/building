## 1. 概述

### 1.1 职责定义

C5 是全部「打得动打不动、打掉多少血」的**结算引擎**：接收攻击发起方（单位指令或设施锚点）与目标集（单位/设施/连接器），按固定结算流程产出伤害与状态结果——命中判定、克制系数、高度修正、掩体标签、死亡连锁触发。C5 **是公式的执行者而非数值的主人**：全部系数（命中基准/克制倍率/高度修正/暴露惩罚/砸落伤害）宿主 F3 表（`combat.json`/`weapons.json`），本文只定义「哪些系数存在、以什么顺序乘在一起、符号方向如何」。

一句话：**把「A 打了 B」变成一份确定、可重放、可追溯的血量变化与状态迁移。**

### 1.2 设计目标与支柱挂钩

| 支柱/定稿项 | C5 落点 |
|---|---|
| P2「高度即力量·占位先于火力」 | 高度修正是结算一等输入：`heightDiff` 正值=守方高位=命中/伤害增益；垛口掩体标签减伤；「占位」的价值在结算数字上兑现（本文 §2.4） |
| P1「一墙之隔，两种战争」 | 垂直打击克近战攀爬（滚木礌石/垛口堵击 vs 云梯人潮）、床弩克骑射集群——克制系数表是「两种战争」的数学表达（§2.4，克制三原则①无万能解：任何倍率组合都留反制缺口） |
| P4「濒危险胜」 | 伤害确定性（无隐藏暴击）+ 死亡连锁即时可读——玩家每轮都能精确推演「下一击谁死」；最后一格血的对赌公开透明 |
| 决策⑥ 引擎无关 | 结算为纯 TS 函数：输入（快照引用+目标集+种子流游标）→ 输出（结算报告），零 Three.js 依赖，X5 对拍地基 |

### 1.3 非目标（Non-goals）

- ❌ 「是否可攻击/打谁」的资格与选择 → C2 §2.4.1（单位域）/C3 targetPriority（设施托管面）/C8（AI 决策）。
- ❌ 位移执行（坠落落位/击退不存在）→ F1（E2 链）/C1（常规移动）。
- ❌ 命中与伤害的**数值定值** → F3 表宿主（本文给键名、结构、符号约定与 MVP 工作假设初值 ⚠）。
- ❌ 相位窗口与结算时点 → F2（E10：伤害仅 C 相位；齐射锚点归 C4）。
- ❌ 士气/溃退/光环 modifiers 的语义解释 → C11（Alpha）/C2（合成入口 C2.7，C5 只消费合成结果）。
- ❌ 攻城器械（投石机等）→ Alpha，仅 §2.7 留接口位。

## 2. 机制

### 2.1 结算总流程（单次攻击事务）

```
① 入口校验：攻击已由 C2 §2.4.1/C3 判定资格——C5 不复检资格，只校验
   目标在结算瞬间仍合法（存活/在场/设施非 DESTROYED——C3-E9 同纪律：结算瞬间复核）
② 目标集物化：按攻击类型物化目标列表（近战=单目标；床弩=§2.2 走廊目标集；
   礌石=§2.5 链式单目标），ON_CONNECTOR 一律取逻辑位置格
③ 逐目标结算（目标间顺序=§2.3 固定序）：
   命中判定（F4 骰）→ 修正合成（C2.7 光环合成结果 + 高度 + 掩体 + 暴露）→
   伤害计算 → hp 回写（C2 applyDamage）→ 死亡检查（C2.3）
④ 结算报告落账：{attacker, targets[], perTarget{hit, dmg, killed}, seedCursor}
   ——事件流可重放（X5/F5），P4 战报订阅
```

- **C5 不写 hp/不迁状态本体**：全部经 C2 `applyDamage`/`eliminate`、F1 `destroyConnector` 白名单 mutation 落地——「谁的数据谁写」纪律（F1 §3.6/C2 §3.5 同源）。
- **结算瞬间复核**：目标在③执行到它之前死亡（如走廊前段目标被杀触发连锁），后段目标仍按当前状态结算；已消失目标按 MISS 落账不重算走廊（§5-E4）。

### 2.2 床弩穿透弹道走廊（R2 终裁定版）

**终裁结论**：「穿透一列」语义 = **俯射弹道走廊**（C3 §2.2 提案，本文正式定版；spike §6 回证性能非约束——网格步进 0.28μs/发 vs 真射线 115μs/发，裁决点纯为玩法语义，**采纳网格语义，禁用真射线**）：

- **走廊形状**：自床弩格沿 `facing` 的 ±x 轴向直线延伸 `range` 格（C3.1 公式）；走廊为**同层格序列**（h=1 墙顶线为主），不因俯射跨层弯折；
- **目标集**（C3.2 公式的 C5 消费语义）：走廊途经格上**全部敌阵营占位**——
  - 垛口/马道上的敌方登城单位（逐格逐单位，GROUND 同理俯射覆盖地面层目标——克制表「床弩克骑射手」的物理前提）；
  - **梯上单位**：`ON_CONNECTOR` 取逻辑位置=梯底格（c.from），梯底格在走廊内即被覆盖——「垛口一线排靶」的惩罚面；
  - 逐目标**独立**命中判定与修正（走廊穿透≠范围溅射，每人各掷各的）；
- **友军豁免**：守方单位不进目标集（C3-E2，阵营过滤在目标集物化时完成，穿透不停滞不遮挡）；
- **WALL 不阻挡**：墙顶武器俯射，墙体结构格不截断走廊（V6 校验保证走廊界外无格）；
- **否决备选模型**：「同层直线仅 h=1 目标」不满足克制表（打不到地面骑射手）——C3 §2.2-B 已判非推荐，本文随终裁正式关闭；「跨层真射线」性能可行但语义漂移（穿层命中与格容量语义脱钩、可读性差、确定性 tie-break 复杂化），**列为不做**（§10 OQ 状态：关闭）。
- **数值预算背书**（程基岩交割①）：10 床弩齐射 × range 12 格 × 全格占满最坏情况 ≈ 3μs 网格步进总开销，性能永非瓶颈。

### 2.3 结算顺序（多目标/多来源的固定序，确定性要求）

1. **单次攻击内目标序**：走廊目标集按**距离床弩格的轴向序**（近→远）结算——先手结算优先的微观化：近处目标先死，远处目标照常结算（穿透语义=逐个都要过骰，非链式截断）。
2. **同锚点多来源序**：齐射时多床弩各自独立结算（C3-E4 无协同加成），来源间顺序=`facilityId` 字典序（确定性，无玩法含义）。
3. **死亡连锁深度**：连锁只触发一层（§2.1④→F2.3 域内清理），连锁引发的连锁不递归——由下一行动序次自然处理（F2 世界冻结+槽序已保证秩序，C5 不自造递归）。

### 2.4 修正合成与高度语义（P2 支柱的数学落点）

修正合成公式（C5.3）：`finalMod = 1 + Σ modifiers`，来源四类、顺序无关（加法合成后一次乘算）：

| 修正源 | 键（F3 宿主） | 符号约定 | 说明 |
|---|---|---|---|
| 光环 modifiers | C2.7 合成结果 | delta 有符号 | C5 只读消费合成值，不解析 auraStrategy |
| 高度差 | `heightMod per level`（MVP ⚠ 0.10/层） | `heightDiff(target, attacker) > 0` = 守方高位：守方受击减益、攻方命中/伤害增益各吃一层；**负向对称**（高打低增益）——方向唯一由 F1 heightDiff 符号裁定（b.h − a.h），程基岩交割③已对表 | 每层 ±10% 线性，Alpha 可改曲线 |
| 掩体标签 | `coverMod parapet` | 垛口（PARAPET）上受远程命中减伤 | 垛口=掩体的机制价值（F1 meta 标签消费） |
| 暴露态 | `exposedMod ladder` | 梯上（ON_CONNECTOR）受命中增伤 | 「爬城即险途」（C1 §2.4 等待者暴露的结算面） |

- **高度语义锚点**：梯上单位 `heightDiff` 按逻辑位置格（h=0 地面）计——攀爬中不享受任何高位修正，顶端未落位前全程吃暴露惩罚：**「高度即力量」必须在落位那一刻才兑现**（占位先于火力的激励精确性）。
- **climb 联动**（程基岩交割⑥）：C1 BLOCKED_TOP 排队者受击按同口径增伤——排队长龙=高价值集火面，守方「堵住让梯上叠人」的打法有结算回报，攻方被迫分批投放：**攀爬经济与受击经济互为压力**。`moveCost climb`（F3）若平衡期调参，需联动复核 `exposedMod ladder`（两键共担「爬城一拍」的风险收益曲线）——已列 §10 平衡联动注记。

### 2.5 礌石毁梯结算序（先位移后伤害，固定序成文）

投放资格判定在 C3（`canDrop` C3.5：曼哈顿+轴向度量，v1.0.2 已钉死）；C5 承接其后的**效果结算链**，固定序如下（**顺序是裁定，不可交换**——程基岩交割④，本文定版）：

```
① SPENT：stock.state=ARMED→SPENT（C3 落账，弹药唯一消耗点，先于一切效果——
   防止后段失败时弹药凭空回滚的重复结算歧义）
② 毁梯：F1 destroyConnector(ladderId)——原子断边+清 occupancy（INV6 单事务）
③ 坠落位移：F1 E2 链——梯上单位按 from格/同层顺延/OFFBOARD 兜底落位
   （F1 裁定落点，「梯毁单位必有着落」单向保证，落位失败不回滚 destroy）
④ 砸落伤害：C5 dropDamage 结算——对位移后位置判定；
   伤害只作用于梯上原单位（C3.6：恒 1 人，无范围歧义）；
   坠落伤害（F1 E2 的自由落体分量）与砸落伤害（礌石动能分量）**两条入口分立**
   ——数值分别挂 F3 键 fallDamage / dropDamage（C1-E1/F1 OQ-2 的 C5 侧收口），
   语义独立可各自调参，玩家侧统一表现为「摔下来还挨砸」
⑤ 残骸标记：F1 E5 链（P1 演出，与结算无关，时序尾随）
```

- **为何先位移后伤害**：伤害若先于位移，则「致死时人在梯上」与「致死时人已落地」会导出两种死亡位置与两种连锁路径（死亡时 occupancy 是否需清）——固定序消掉这棵歧义树；先位移后伤害保证死亡判定发生时单位已在最终位置，`eliminate` 链路（含 X2 抚恤/C9 计数）入口唯一。
- **结算序在事件流中的可观测性**：五步各自发事件且顺序固定——X5 重放断言可逐事件对拍（BE-2）。

### 2.6 梯上受击与攀爬交互面（C1/F1 边界的 C5 收口）

| 场景 | 受击面裁定 | 归属链 |
|---|---|---|
| 攀爬中（occupancy 登记）被近战 | 可近战（逻辑位置=梯底格，C2 §2.4.1），无高度修正增益 | C5 常规近战结算 |
| 攀爬中被床弩走廊覆盖 | 梯底格在走廊内即命中判定，吃 exposedMod | §2.2 走廊结算 |
| 攀爬中梯被毁 | §2.5 链（坠落+砸落两条入口） | C3 触发→F1 位移→C5 伤害 |
| 攀爬中被击杀 | F1 removeUnit 同事务清 occupancy（F1 v1.4.1 裁定，击杀链无需 unboard 前置）→ 连接器即时可用 → 排队者下个行动序次正常发起（C1-E2） | C5→C2.3→F1 |
| BLOCKED_TOP 排队中被击 | 同攀爬中口径（排队也是 ON_CONNECTOR） | 本节+§2.4 climb 联动 |

- **F1 OQ-2（攀爬中被击）销账**：上表即终裁——被击资格/受击面在 C5（本节），occupancy 清理在 F1（removeUnit 覆盖裁定），位移在 E2 链，伤害数值双键分立（§2.5④）。四段各归其位，无悬空。

## 3. 数据

### 3.1 结算请求与报告

```ts
interface StrikeRequest {
  attacker: UnitId | FacilityId;        // 单位攻击（C2 资格已过）或设施齐射（C4 锚点触发）
  kind: 'MELEE' | 'CROSSBOW_VOLLEY' | 'ROLLING_STOCK';
  primaryTarget?: UnitId | FacilityId;  // 近战单目标 / 床弩手动锁定偏好（自动索敌归 C3）
  corridor?: { origin: CellId; dir: Dir; range: number };  // CROSSBOW_VOLLEY 必带（C3.1 物化）
  ladderId?: ConnectorId;               // ROLLING_STOCK 必带（毁梯链目标）
}

interface StrikeReport {
  seq: number;                          // 结算流全局序号（确定性对拍锚）
  attacker: UnitId | FacilityId;
  perTarget: Array<{
    target: UnitId | FacilityId;
    posAtStrike: CellId;                // 结算瞬间逻辑位置（梯上=梯底格）——先位移后伤害的可追溯凭据
    hit: boolean;
    mods: { aura: number; height: number; cover: number; exposed: number };  // 逐项落账，P4 战报可解释
    dmg: number;
    killed: boolean;
    chainEvents: string[];              // 死亡连锁触发的事件名（光环清理/波次计数…）
  }>;
  seedCursorBefore: number;             // F4 游标快照（before/after 夹逼校验）
  seedCursorAfter: number;
}
```

`StrikeReport` 是 P4 战报、X5 对拍、F5 回放三方共读的**唯一结算凭据**——逐目标 mods 全量落账，玩家可解释（「这刀为什么疼」每个系数都能指出来）。

### 3.2 F3 表键清单（C5 数值宿主，本文零硬编码；表改动需过平衡评审）

| 键 | 含义 | 宿主表 | MVP 工作假设 ⚠ |
|---|---|---|---|
| `hitBase` | 命中基准概率 | combat.json | 0.75 |
| `heightMod per level` | 每层高度差修正 | combat.json | ±0.10 |
| `coverMod parapet` | 垛口掩体减伤 | combat.json | −0.15 |
| `exposedMod ladder` | 梯上暴露增伤 | combat.json | +0.25 |
| `fallDamage` | 坠落伤害基准（E2 自由落体分量） | weapons.json | 待灰盒 |
| `dropDamage` | 砸落伤害基准（礌石动能分量） | weapons.json | 待灰盒 |
| `crossbow.damage` | 床弩单发伤害 | weapons.json | 待灰盒 |
| `meleeMod vs facility` | 近战对设施伤害系数 | weapons.json | 待灰盒 |
| `squadHpPowerCurve` | 残队战力折扣曲线（C2 OQ-3 承接） | combat.json | 线性 hp 比例 |

## 4. 公式

> 统一格式：编号 ｜ 名称 ｜ 变量与单位 ｜ 表达式 ｜ 消费方。数值基准一律标「F3 表宿主」。

- `C5.1 ｜ 目标集（走廊）：T = {u | pos(u) ∈ Line(origin, dir, range) ∧ faction(u)=攻} ｜ pos(ON_CONNECTOR)=c.from ｜ Line=C3.1 ｜ 消费方：C5/P1/C3`
- `C5.2 ｜ 命中判定：hit(u) ⇔ rand(F4) < hitBase + modsSum(u) ｜ rand∈[0,1) 经 F4 种子流固定游标 ｜ modsSum=§2.4 四源加法合成 ｜ 消费方：C5/X5`
- `C5.3 ｜ 修正合成：modsSum = aura + heightDiff(target,attacker)×heightModPerLevel + cover(target) + exposed(target) ｜ heightDiff 符号=F1（b.h−a.h，正=目标高位）｜ 消费方：C5/P4`
- `C5.4 ｜ 伤害：dmg(u) = base(kind) × squadFactor(hpRatio) × (hit ? 1 : 0) ｜ base 宿主 F3（weapons.json）；squadFactor=squadHpPowerCurve（戍卒小队，C2 OQ-3 承接，MVP=hp 比例线性）｜ 消费方：C2 applyDamage`
- `C5.5 ｜ 坠落双入口：totalFallDamage = fallDamage（E2 分量）+ dropDamage（礌石分量，仅 ROLLING_STOCK 链）｜ 两键独立宿主 F3 ｜ 消费方：C2（hp 回写）、F1 OQ-2 收口`
- `C5.6 ｜ 死亡触发：killed ⇔ hp'(u) = 0 ｜ hp' 由 C2.2/2.3 判定与迁移，C5 只落账 ｜ 连锁深度=1 ｜ 消费方：C2/C6/C9/P1`
- `C5.7 ｜ 走廊目标结算序：ord(u) = 轴向距离(origin→pos(u)) 升序，等距按 unitId 字典序 ｜ 确定性硬约束 ｜ 消费方：C5/X5`
- `C5.8 ｜ 种子游标推进：每次 rand(F4) 调用游标 +1，调用序=§2.3 结算发生序 ｜ 重放校验：seedCursorBefore/After 夹逼 ｜ 消费方：X5/F5`
- `C5.9 ｜ 对设施伤害：dmgFacility = meleeMod vs facility × base(MELEE) ｜ 走 C5→C3 currentHp 落账，摧毁判定归 C3.7 ｜ 消费方：C3（C3-E5 场景）`

### 4.1 不变量（可单测）

- INV-C5-1：结算事务原子性——任一 StrikeReport 提交后，无「已扣血未判死」「已断梯未落账」中间态（fuzz 断言）。
- INV-C5-2：同（世界快照，StrikeRequest 序列，F4 种子）→ StrikeReport 流逐字节一致（重放）。
- INV-C5-3：结算瞬间复核——`hit(u) ⇒ u 在结算到达该目标时 isAlive(u) ∧ 在场`（C3-E9 同纪律；不满足则 MISS 落账）。
- INV-C5-4：`seedCursorAfter − seedCursorBefore = 本次结算 rand 调用数`（游标推进与结算序严格同相）。
- INV-C5-5：修正合成方向性——`heightMod` 项符号恒与 `heightDiff` 同号（方向性回归测试，防约定反转）。

## 5. 边缘情况

> 裁定者=本文；位移归 F1、资格归 C2/C3、时点归 F2。格式：编号｜场景｜裁定｜消费方。

### A. 弹道与目标集

- **C5-E1｜走廊中段目标先死**：按 §2.3 近→远结算，中段死亡触发连锁（光环清理等）**不影响**后段目标结算——穿透语义=逐目标独立过骰，非链式截断；后段目标若因连锁而消失（深度 1 连锁只清 buff 不杀人，此场景 MVP 不存在，防御性裁定）：按 INV-C5-3 MISS 落账。
- **C5-E2｜锁定目标在齐射锚点前死亡**：C3-E3 同源——锁定为偏好，发射瞬间复核存活，亡则按 targetPriority 自动补选同方向次优目标；无目标则空转不耗装填（C3.4）。C5 侧表现为 StrikeRequest.primaryTarget 指向已亡单位时忽略偏好按自动序物化。
- **C5-E3｜友军站进走廊**：豁免（目标集物化时阵营过滤，C3-E2）——友军不进 T、穿透不停滞；不存在「挡枪」战术（MVP 有意如此：豁免=免按键的简单规则，误伤复杂度留给 Alpha）。
- **C5-E4｜结算中途目标格被第三方占位变化**：不存在——F2 行动槽世界冻结（C1 §2.5 继承），结算期间无并发变更；齐射多来源间亦按 C5.7 序串行。
- **C5-E5｜冲车在走廊/近战范围内**：冲车 `immuneToMeleeInteract=true`（近战不可及，C2 §3.3）；但**可被床弩走廊命中**吗？——裁定：**MVP 床弩目标集含冲车**（它不是「近战交互」而是弹道命中，immune 旗标只管单位域近战；克制上床弩打冲车效率由克制系数表定，若需特攻挂 `crossbow vs structure` 键位，MVP 恒 1.0）。近战侧：戍卒永远打不到冲车（资格在 C2 已拒，C5 不复检）。
- **C5-E6｜双梯同落点格，梯上各 1 人**：两人逻辑位置=同格——走廊命中判定对**每个单位独立**（逐 UnitId 结算，非按格合并一骰）；§2.3 序内按 unitId 字典序。与 C1 OQ-5（已销账 M-5：occupancy 相互独立）口径自洽。

### B. 毁梯与坠落

- **C5-E7｜梯上无人被砸**：允许投放（C3-E7），dropDamage 无对象——§2.5 ④ 空转，仅 fallDamage 亦无对象（无人坠落）；报告落账 `perTarget=[]`，弹药照耗。
- **C5-E8｜坠落落位至 OFFBOARD 兜底后遭砸落伤害**：伤害照常结算（posAtStrike=兜底落点；若致死，死亡位置=OFFBOARD 侧，抚恤/缴获链不受影响）——「先位移后伤害」固定序的必然结论：**伤害对象是单位而非位置**。
- **C5-E9｜梯毁时梯上单位恰好是督队**：§2.5 链正常走完（位移→伤害→死亡检查），若致死触发 C2-E9 光环清理连锁（深度 1）——督队尸落地面，光环即灭，同相位后续单位 modifier 合成已不含死者（先手结算优先，不回溯）。
- **C5-E10｜同一梯同轮双礌石竞速**：C3-E8 同源——第二指令到达时梯已 DESTROYED，`canDrop` NO_LADDER 拒绝且不消耗；C5 侧不可达（§2.5 ① SPENT 前置校验在 C3 canDrop，双保险）。

### C. 死亡与连锁

- **C5-E11｜同一次结算击杀连锁目标死亡**（走廊一次穿杀带光环单位+其受益单位）：深度=1——光环清理即时生效（C2-E9），受益单位本已在 §2.3 序中排队，其结算时的 mods 合成按**结算到达时点**取值（含/不含光环取决于它在序中的位置）——确定性由 C5.7 序保证，无歧义。
- **C5-E12｜戍卒小队残队被击杀**：squadFactor 按 hp 比例缩放伤害**输出**；受击侧无额外缩放（hp 池即防御，不双重折算）——`squadHpPowerCurve` 只挂 C5.4 输出侧（C2 OQ-3 销账口径）。
- **C5-E13｜致死与 morale/悬赏事件并发**：killed 事件单点发出（C5.6），C6 赏格/C9 计数/P1 演出各自订阅——事件分发给，顺序各归其主（F2 D 相位结算序兜底），C5 不组合跨域效果。

### D. 确定性与异常

- **C5-E14｜F4 游标在结算中异常**：INV-C5-4 夹逼校验失败即判结算无效并回滚整个 Strike（事务性）——回滚=报告丢弃+状态由 C2/F1 白名单逆向补偿（MVP 实现=结算前快照恢复，快照成本 O(变更集) 可忽略）；该路径是纯护栏，fuzz 断言其 MVP 恒不触发。
- **C5-E15｜read档后重放同一攻击**：F5 存档含 seedCursor 快照——读档→同指令→同报告（INV-C5-2），「打过了的骰子不会重摇」。
- **C5-E16｜C 相位外的 strike 请求**：拒绝（ResolutionCommand 窗口校验=F2 E10 断言的实现面）；修理/建造等 A 相位动作不经 C5。
