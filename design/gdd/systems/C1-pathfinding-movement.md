## 1. 概述

### 1.1 职责定义

C1 是分层图上的**路径计算与移动执行服务**：给单位（持有移动点 MP）与目标格，产出一条合法路径并逐步原子执行；跨层位移一律经 F1 连接器（坡道/云梯/GATE 同一模型）。C1 消费 F1 的邻接图与容量申请接口，本身**不持有任何地形状态**——地形问 F1，数值问 F3，单位属性问 C2。

一句话：**把「我想让这个单位去那儿」变成一串合法、确定、可回滚的脚步。**

### 1.2 设计目标与支柱挂钩

| 支柱/定稿项 | C1 落点 |
|---|---|
| P2「高度即力量·占位先于火力」 | 攀城点容量 1 + 梯顶封顶（F1.11）→ C1 的攀爬时序是「占位先于火力」的执行引擎：谁先到顶谁占位 |
| P4「濒危险胜」 | 攀爬单列通行（capOcc=1）制造登城瓶颈，攻方波次的涌堵感、守方堵口的紧张感都由移动结算节奏承载体现 |
| MVS 条件 3 | **正式采纳「云梯=动态连接器」**：C1 将 LADDER 与 SLOPE/GATE 视为同一种图边，仅 lifetime/status 不同，零特殊分支 |
| 决策⑥ 引擎无关 | 路径算法为纯 TS 模块，输入输出均为 F1 数据契约，不感知 Three.js |

### 1.3 非目标（Non-goals）

- ❌ 单位 MP 基准值、层位许可 flag、体型占位（footprint）定义 → C2（本文只消费其接口）。
- ❌ 匈奴「去哪爬哪面墙」的决策 → C8（C8 下达移动指令，C1 负责执行）。
- ❌ 托管模式下「该不该移动」的判断 → C10（经同一套移动指令 API 下单，无特权通道）。
- ❌ 梯上受击修正、坠落伤害数值 → C5（C1 只执行 F1 E2 的位移裁定）。
- ❌ 移动范围/路径的可视化表现 → P3/P4（本文提供查询接口与语义）。
- ❌ 推挤/换位/区域控制（ZOC）→ MVP 不做（F1 E9 同源裁定），Alpha 候选。

### 1.4 关键裁定速览（TL;DR）

| # | 裁定 | 一句话 |
|---|---|---|
| A | 算法选型 | **A\*（逐指令计算）**，不做 flow field——回合制+单位≤80，逐单 A* 绰绰有余；flow field 的缓存失效复杂度（动态梯频繁改图）在 MVP 是纯负债 |
| B | 移动资源 | 移动点 MP（每单位每轮，C2 表宿主）；按格消耗：平移 1 / 门洞 2 / 连接器攀爬 2（F1 TerrainRules 键，F3 宿主）；剩余 MP 不累计不预支 |
| C | 攀爬原子性 | 攀梯/登坡为**单动作原子完成**（发起时 MP≥攀爬消耗即一次到位），杜绝「卡在梯子中间跨回合」；顶格满则攀爬者**留梯等待**（F1.11 排队语义），下个自身行动序次重试 |
| D | 执行时序 | 严格串行：单位按速度序逐个行动，行动内世界冻结；路径在**行动开始时计算**，整条预检+逐格原子落格双保险 |
| E | 确定性 | 固定邻居展开序 + 字典序 tie-break + 节点预算上限——同种子同指令序列必得同路径（F4/X5 对拍地基） |
| F | 中断规则 | 执行中遇格被占（仅同相位先行单位可致）→ 停在最后可达格，已耗 MP 不退（F1 E8 回滚语义的 C1 侧执行） |
| G | 缓存策略 | MVP **无跨行动路径缓存**（行动开始即算）；仅回合内同单位重试复用，梯毁/占位变化即弃 |

## 2. 机制

### 2.1 移动模型总览

- 每个可移动单位每轮持有 `MP（移动点）`，基准值按单位类型定于 C2/F3 表（MVP 工作假设：戍卒 3 / 匈奴步兵 3 / 骑射手 5 / 督队 4，**数值归 C2，本文不裁定**）。
- 一次移动指令 = `(unitId, targetCellId)`；C1 计算消耗最低路径（消耗同长时按确定性 tie-break 取一，§4.5），逐格执行并扣减 MP。
- MP 是移动专用资源，与行动点（C2/C5 的攻击/技能经济）分立；「移动后可否攻击」归 C2 行动经济裁定，C1 只报告本次移动消耗。

### 2.2 步进消耗语义

| 位移类型 | 消耗 | 数据来源 |
|---|---|---|
| 层内平移（GROUND/RAMPART_WALK 等 passable 格） | 1（`moveCost plains`） | F1 §4.5 键，F3 宿主 |
| 进入 GATE 门洞格 | 2（`moveCost gate`） | 同上 |
| 经连接器跨层（坡道上行/下行、云梯攀爬） | 2（`moveCost climb`），**不分方向同价**（MVP 简化；Alpha 可分向调价，键位预留 `moveCost descend`） | 同上 |

- 连接器攀爬消耗为**整段一口价**，与「跨了几个高度层」无关（MVP 全部连接器跨 1 层，烽燧内部坡道 h0→h2 按 1 条边计 2——F1 §2.2 已裁定烽燧梯一步直达）。
- 路径的每一格都必须 `passable` 且通过容量预检（F1 `canPlace`）；连接器边必须 `status=ACTIVE` 且 `canBoard`（F1 F1.10）。

### 2.3 层位许可（edge 过滤，数据归 C2）

- 单位数据带 `layerAccess: Height[]`（如骑射手=[0]，步兵=[0,1]，戍卒=[0,1,2]）——**flag 在 C2，过滤在 C1**：路径搜索时，通往无许可层的连接器边按不存在处理。
- 语义结果：骑射手在「唯一通道是梯/坡」的残局中显示「不可达」而非「路径绕行」——这正是 Q4 裁定「马不上墙」的执行面。

### 2.4 攀爬时序（本系统最核心的节奏机制）

一次完整的登梯流程（坡道同理，唯不可摧毁）：

```
① 发起    单位在梯底格（from），行动序次到来，MP ≥ climb(2)
          └─ 检查 canBoard(connector)（ACTIVE + occupancy 空）
② 攀爬    整段原子执行：扣 2 MP，单位迁入 connector.occupancy
          （F1 状态 → ON_CONNECTOR，逻辑位置仍=梯底格）
③ 登顶    即刻尝试 F1.11：canPlace(to, 1)
          ├─ 顶位空 → 落位顶格，occupancy 清空，动作完成
          └─ 顶位满 → 攀爬者留梯等待（保持 ON_CONNECTOR），
             等至自身下个行动序次重试 ③；等待不耗 MP
④ 撤离    留梯玩家/AI 可选择主动退回 from 格（不耗 MP，动作结束）；
          梯被毁 → F1 E2 坠落（位移 F1 执行，伤害 C5 结算）
```

- **为什么攀爬必须原子**：若允许「半梯」状态跨回合，需要为梯中单位定义受击面插值、渲染插值、与登顶判定的一堆中间态；MVP 用「发起即整段」换掉整类边缘情况。节奏上 2 MP 一段攀爬已足够制造「爬城一拍」的时间感（P4 支柱）。
- **等待者暴露**：留梯等待的单位处于 `EXPOSED` 梯上暴露态（标签 F1 给、修正 C5 定）——顶位被堵的匈奴在梯上干瞪眼，是「垛口堵击」爽感的直接来源。
- **多点并发的天然串行化**：每条连接器 occupancy 容量 1，多梯+坡道并行承压时互不干扰（F1 E13），C1 无需全局锁。

### 2.5 执行时序与中断规则

- 攻防结算相位按速度序逐单位行动（概念稿 C 阶段）；**任一单位行动期间世界状态冻结**（无并发结算），因此路径预检结果在执行期内可靠。
- 执行流程：行动开始 → 读 MP → 计算路径 → 整条逐格预检（容量+许可+边活性）→ 逐格原子落格（F1 `moveUnit`，INV4 原子性兜底）→ 扣减 MP → 返回执行报告。
- **中断（E8 场景，仅一源）**：同相位内先行单位落格占满后格——先手结算优先，当前单位停在最后可达格，剩余 MP 保留，执行报告标注 `interrupted: true` 及断点位；玩家侧下一指令重新规划。已完成的段次不回滚（F1 E8 语义）。

### 2.6 确定性纪律（X5 模拟器对拍的前提）

1. 邻居展开固定序：四邻按 `(+1,0) → (-1,0) → (0,+1) → (0,-1)`，连接器边按 `connectorId` 字典序追加（§4.5）。
2. 等长路径 tie-break：取路径格序列字典序最小者。
3. 所有随机因素（未来若有，如 Alpha 绕袭偏好）必须经 F4 种子随机源，禁止 `Math.random`。
4. 同 (图状态， 指令序列， F4 种子) → 逐字节一致的重放——X5 批量对拍与存档回放（E16）共同依赖此性质。

## 3. 数据

> 引擎无关 TS。C1 自身仅持短期过程数据（开闭集、路径缓存），不持有任何持久状态——持久状态全在 F1（地形）与 C2（单位）。

### 3.1 移动指令与执行报告

```ts
interface MoveOrder {
  unitId: UnitId;
  target: CellId;
  mode: 'MANUAL' | 'AUTO';        // AUTO=托管/AI 下单，走同一 API，无特权
  expectTopRetry?: boolean;       // 攀爬等待语义：允许留梯（见 §2.4③）
}

interface MoveReport {
  status: 'COMPLETED' | 'PARTIAL' | 'BLOCKED_TOP' | 'REJECTED' | 'UNREACHABLE';
  executed: CellId[];             // 实际落格序列
  mpSpent: number;
  interrupted?: { at: CellId; reason: 'CELL_FILLED' };   // §2.5 中断
  waitingConnector?: ConnectorId; // BLOCKED_TOP：留梯等待中
  rejectReason?: 'NO_MP' | 'NO_LAYER_ACCESS' | 'INVALID_TARGET' | 'NODE_BUDGET';
}
```

`BLOCKED_TOP` 不是失败：单位已上梯等待，指令「部分成立」——C8/C10 据此决定换目标、原地待命或继续等。

### 3.2 路径与查询结果

```ts
interface PathStep {
  cell: CellId;
  viaConnector?: ConnectorId;     // 本步是跨层步时携带
  cost: number;                   // 本步消耗
}

interface PathResult {
  steps: PathStep[];
  totalCost: number;
  deterministic: true;            // 构建即承诺：同输入必同输出
}
```

### 3.3 对外只读查询接口（MoveQuery，供 §6 契约）

```ts
interface MoveQuery {
  reachable(unitId: UnitId): ReachableMap;      // MP 预算内可达集+最小消耗（Dijkstra 泛洪）
  pathPreview(unitId: UnitId, target: CellId): PathResult | null;  // 纯预览，不改状态
  canClimb(unitId: UnitId, connId: ConnectorId): {ok: boolean; reason?: string}; // 攀爬发起预检
  lastReport(unitId: UnitId): MoveReport;       // 供 UI/C10 复盘
}
```

`ReachableMap = Record<CellId, {cost: number; blockedTop?: boolean}>`——`blockedTop` 标记「可达但为满顶格的梯顶」，UI 据此区分绿/黄显（§6.1）。

### 3.4 与 F1/C2 的读写边界

| 数据 | C1 权限 | 说明 |
|---|---|---|
| 邻接图/连接器状态 | 只读（F1 TerrainQuery） | 路径合法性的唯一依据 |
| 格占用（occupantIds） | 经 F1 `moveUnit` mutation 间接写 | C1 不直接碰 occupantIds |
| connector.occupancy | 经 F1 写白名单（攀爬登记由 moveUnit 的连接器段完成） | 承载登记原子性归 F1 INV2 |
| 单位 MP / layerAccess | 只读（C2 接口） | 基准值与扣除后回写均归 C2 |

## 4. 公式

> 统一格式：编号 ｜ 名称 ｜ 变量与单位 ｜ 表达式 ｜ 消费方。数值基准一律标「F3 表宿主」。

- `C1.1 ｜ 步进消耗：stepCost(cell) = TerrainRules.moveCost[kind→键] ｜ 平移 1 / 门洞 2 ｜ 宿主 F3（terrain-rules.json）`
- `C1.2 ｜ 跨层步消耗：stepCost(connector) = TerrainRules.moveCost.climb = 2（MVP 不分方向同价）｜ 宿主 F3`
- `C1.3 ｜ 路径总消耗：totalCost(P) = Σ stepCost(stepᵢ) ｜ P 为 CellId/Connector 交替序列`
- `C1.4 ｜ 可达集：R(u) = {c | minCost(u → c) ≤ MP(u) ∧ 逐格合法} ｜ minCost 由 Dijkstra 泛洪求得（UI 范围显与寻路同源）`
- `C1.5 ｜ A\* 评估：f(n) = g(n) + h(n)，h = 曼哈顿距离 × min(stepCost) = d × 1 ｜ 一致性启发（admissible & consistent），保证首达即最优`
- `C1.6 ｜ 邻居展开序：[(+1,0), (-1,0), (0,+1), (0,-1)] + 连接器边按 id 字典序 ｜ 确定性硬约束（§2.6）`
- `C1.7 ｜ 攀爬发起：canClimb(u, c) ⇔ MP(u) ≥ C1.2 ∧ c.status = ACTIVE ∧ canBoard(c) ∧ layerAccess(u) ∋ h(c.to)`
- `C1.8 ｜ 登顶判定：落顶 ⇔ canPlace(c.to, 1)（F1.11 先到先得）；失败 → BLOCKED_TOP 留梯`
- `C1.9 ｜ 扣费：MP'(u) = MP(u) − Σ stepCost(executed) ｜ 中断时只计已执行步`
- `C1.10 ｜ 节点预算：A\* 展开节点数 ≤ 2000，超限即判 UNREACHABLE ｜ 图 ≤400 格时不可触顶，纯护栏（防空图死循环）`

## 5. 边缘情况

> 裁定者=本文；数值归 C5/C2。格式：编号｜场景｜裁定｜消费方。

### A. 攀爬与连接器

- **C1-E1｜攀爬者留梯期间梯被毁**：F1 E2 坠落链路接管（位移 F1、伤害 C5）；C1 侧表现为该单位行动序次到来时已不在梯上（`lastReport` 保留 BLOCKED_TOP 记录供复盘）。等待者**不产生额外伤害**（坠落伤害语义只针对「被毁时在梯」这一状态，梯上仅 1 人，无歧义）。
- **C1-E2｜攀爬者在梯上被击杀**：F1 `removeUnit` 清空 occupancy → 连接器即时可用；梯底等待的后续单位在本轮自身行动序次正常发起（世界冻结已解除并重建，路径按行动开始时状态计算，无缓存污染）。
- **C1-E3｜MP 不足以发起攀爬**：指令 REJECTED（`NO_MP`），原子拒绝——**不存在「先上梯下轮续爬」**（§2.4 裁定）。UI 语义：攀爬按钮按 MP 灰显并显示「需 2 移动点」。
- **C1-E4｜主动弃梯**：留梯单位可逆爬返回 from 格（0 MP，动作结束）；顶格满且玩家不想等时这是标准撤退操作。坡道不存在留梯态（顶满则根本发起不了——坡道顶多为马道，容量 2 难满），语义差异恰好反映「梯=险途、坡=常道」。
- **C1-E5｜下坡/顺梯而下**：允许，消耗同为 climb 2（MVP 同价，§2.2）；戍卒经坡道下地面驰援、或梯上单位随梯毁坠落（E2，非主动）是两条不同链路，前者正常移动、后者 F1 强制位移。

### B. 阻塞、中断与回滚

- **C1-E6｜整条预检通过但执行中被占**：唯一来源是同相位先行单位（§2.5）；裁定=停在最后可达格（PARTIAL + interrupted），已耗 MP 不退。玩家单位中断时 P4 弹提示；AUTO 模式 C8/C10 收报告自行决策。
- **C1-E7｜目标格本身满员**：预检阶段即 REJECTED（`INVALID_TARGET`），**不做「走到旁边最近空格」的智能降级**——降级会破坏玩家对指令的精确预期；「就近落位」若产品上需要，由上层（P3 提示 / C10 决策）显式重下指令，C1 保持笨而可靠。
- **C1-E8｜两单位先后指令同一目标格**：速度序天然串行，先者执行后后者行动开始时重算——图已变化，自然得新路径或拒绝。无需锁。
- **C1-E9｜路径穿过满顶格的梯（blockedTop）**：泛洪时该梯顶格标记 `blockedTop` 进入可达集但**不可作为最终落点**；可作为「路径中继」的场景不存在（梯顶格无穿过性——上去即登顶）。UI 黄显警示（§6.1）。

### C. 确定性与性能

- **C1-E10｜等长路径多解**：tie-break 取格序列字典序最小（§2.6-2）；单测以固定关卡断言具体路径，防回归。
- **C1-E11｜不可达图的搜索开销**：节点预算 2000 早退（C1.10）；骑射手被层位许可困住（§2.3）是最常见触发源，预算护栏保证「不可达」判定恒快。
- **C1-E12｜梯毁后旧路径引用失效**：MVP 无跨行动缓存（§1.4-G），行动开始即算，天然免疫；唯一缓存=同单位同行动内重试（BLOCKED_TOP 重试③），重试前 revalidate 连接器 status（防梯毁后走幽灵边）。
- **C1-E13｜GATE 被封门（INACTIVE）后的路径**：INACTIVE 边按不存在处理（F1 §6.1 灰显语义）；已下达的移向门洞指令在执行时 REJECTED/重算，语义与「边消失」一致。

### D. 单位差异与扩展

- **C1-E14｜层位许可导致的「孤岛」**：骑射手在无坡道残局中全图不可达梯顶→UI 显「该单位无法登城」（非红色不可达，用专属提示，防误读为 bug）；许可数据归 C2，本文只消费。
- **C1-E15｜冲车移动（挂 F1 OQ-3）**：若 C2 裁定冲车占地面格（2×1 footprint），路径校验扩为**双格原子申请**（footprint 接口预留于 C1.7 扩展位）；若裁定为「不占格的结构攻击实体」，冲车完全不进 C1。**本文两种都兼容，待 OQ-3 关闭后回填本条。**
- **C1-E16｜托管的批量移动结算**：C10 在一次托管结算中按速度序逐单位下发 AUTO 指令，与手动走完全相同的 API 与中断规则——托管不享有路径特权（C10 GDD 复核其决策层，Q5 亦挂彼处）。
